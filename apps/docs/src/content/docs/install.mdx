## Requirements

<Only framework="react">

|                         |                     |
| ----------------------- | ------------------- |
| @lunarhue/forms-react   | React 18 and later, or 16.8 and 17 with the condition below |
| @lunarhue/forms-schema  | Zod 4 or Valibot 1  |
| @lunarhue/forms-bind    | Zustand 5           |

</Only>

<Only framework="solid">

|                         |                    |
| ----------------------- | ------------------ |
| @lunarhue/forms-solid   | Solid 2, or Solid 1.8 and later from `/v1` |
| @lunarhue/forms-schema  | Zod 4 or Valibot 1 |
| @lunarhue/forms-bind    | Solid 2            |

If you're on Solid 1, import from `@lunarhue/forms-solid/v1` instead. It exports the exact same functions and types as the main entry, so upgrading from Solid 1 to Solid 2 is just a matter of updating your import path. Note that `signal()` from `@lunarhue/forms-bind` requires Solid 2—on Solid 1, use `bind()` from `@lunarhue/forms-solid/plugins` instead.

</Only>

## Using React 16.8 or 17

By default, `@lunarhue/forms-react` relies on React 18's built-in `useSyncExternalStore` and `useId`. To support React 16.8 or 17, the package ships a legacy entry with fallbacks for both hooks.

You can opt into it by enabling the `@lunarhue/react-legacy` export condition in your bundler. If you forget to set it on React 17, development builds will fail fast with a `react:legacy` error on load (production builds skip the check and will break when the first form renders).

Here's how to wire that condition up in the most common setups:

**Vite**

```ts
// vite.config.ts
import { defaultClientConditions, defaultServerConditions, defineConfig } from "vite";

export default defineConfig({
  resolve: { conditions: ["@lunarhue/react-legacy", ...defaultClientConditions] },
  ssr: {
    resolve: {
      conditions: ["@lunarhue/react-legacy", ...defaultServerConditions],
      externalConditions: ["@lunarhue/react-legacy"],
    },
  },
});
```

**webpack / Rspack** (keep `"..."` so the default conditions stay intact):

```js
// webpack.config.js or rspack.config.js
module.exports = {
  resolve: { conditionNames: ["@lunarhue/react-legacy", "..."] },
};
```

**esbuild** (setting `conditions` overrides the default `module` condition, so include it explicitly):

```js
await esbuild.build({
  conditions: ["@lunarhue/react-legacy", "module"],
});
```

**Next.js with webpack**

```js
// next.config.js
module.exports = {
  webpack(config) {
    config.resolve.conditionNames = ["@lunarhue/react-legacy", ...(config.resolve.conditionNames ?? ["..."])];
    return config;
  },
};
```

**Next.js with Turbopack** (Turbopack doesn't expose custom export conditions, so alias the internal import directly):

```js
// next.config.js
module.exports = {
  turbopack: {
    resolveAlias: { "#lunarhue/react": "@lunarhue/forms-react/legacy" },
  },
};
```

If Node loads the adapter directly on the server without bundling `node_modules`, pass the condition to Node as well: `NODE_OPTIONS=--conditions=@lunarhue/react-legacy`.

The legacy build works fine on React 18 and 19 too—handy if you're shipping a shared library that needs to support older React versions now and drop the condition later.

</Only>
