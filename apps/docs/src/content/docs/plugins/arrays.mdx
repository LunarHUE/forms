Dynamic lists (like checklists, invoice line items, or multiple phone numbers) need rows you can add, remove, and reorder without losing focus or mixing up field state as items shift around. The `arrays()` plugin handles that: `<Items>` renders one child per row, and array handles expose the commands to modify the list.

## Installing `arrays()`

Add `arrays()` to `createForms` (if most forms have lists) or to a specific form's `plugins`:

```tsx framework=react
import { arrays } from "@lunarhue/forms-react/plugins";

const forms = createForms({ plugins: [arrays()] });
```

```tsx framework=solid
import { arrays } from "@lunarhue/forms-solid/plugins";

const forms = createForms({ plugins: [arrays()] });
```

If you forget to install `arrays()`, passing an array handle to `Items`, `useItems`, or `createItems` (or calling `push`, `insert`, `remove`, or `move`) produces a compile-time error telling you to add `arrays()`. Forms without dynamic lists leave it out and ship less code.

## Rendering rows with `<Items>`

Pass your array handle to `<Items>` and provide a render function that receives each row's handle and current index:

```tsx framework=react
import { Items } from "@lunarhue/forms-react";

<Items handle={form.root.at("tasks")}>
  {(task, index) => <form.TextField handle={task.at("title")} label={`Task ${index + 1}`} />}
</Items>
```

```tsx framework=solid
import { Items } from "@lunarhue/forms-solid";

<Items handle={form.root.at("tasks")}>
  {(task, index) => <form.TextField handle={task.at("title")} label={`Task ${index() + 1}`} />}
</Items>
```

<Only framework="solid">

In Solid, `index` is a reactive accessor (`index()`), so each row mounts once and its label updates when moved. You can also pass a `fallback` prop to render when the list is empty.

</Only>

Notice that we use `task.at("title")` instead of a string name like `"tasks.0.title"`. String indexes break the moment a row moves, whereas row handles stay tied to their item. `<Items>` only re-renders when rows are added, removed, or reordered; typing inside a row never re-renders the list.

## Modifying the list

Grab the array handle with `form.root.at("tasks")` and call its commands directly:

| Command | What it does |
| --- | --- |
| `push(item?)` | Appends a row to the end of the list. |
| `insert(index, item?)` | Inserts a row before `index`. |
| `remove(index)` | Removes the row at `index`. |
| `move(from, to)` | Moves a row from one position to another. |
| `setValue(items)` | Replaces the entire array. |

If you omit `item` on `push()` or `insert()`, the store builds an empty row from your schema (when a schema plugin is installed) or uses `undefined`.

## Stable row keys

Every row gets a stable key when it's created, and both `task.key` and the `task` handle itself stay identical for the lifetime of that row, even as it moves around the list. `<Items>` uses `task.key` automatically so inputs keep their focus and DOM state across reorders. You can inspect the current keys via the array snapshot's `keys`, or look up a row handle with `tasks.item(key)`.

<Only framework="react">

Need custom layout control around the list? Call `useItems(handle)` to get the ordered array of row handles (re-rendering only when keys change), and use `task.key` as your React `key`.

</Only>

<Only framework="solid">

Need custom layout control around the list? Call `createItems(handle)` to get an accessor of row handles (updating only when keys change), and pass it to `<For each={items()}>`.

</Only>

## Arrays without the `arrays()` plugin

You don't need `arrays()` just to hold an array in form state, for example a multi-select or tag list replaced wholesale via `setValue`. You just can't render individual rows with `Items` or call row-level commands (untyped calls throw [`arrays:missing`](/errors#core:arrays:missing) in development and no-op in production).

Under the hood, without `arrays()`, keys are positional (`k0`, `k1`, ...). That means state like `touched` belongs to the slot rather than the item: replacing `["a", "b", "c"]` with `["a", "b"]` and then `["a", "b", "d"]` reuses slot `k2` along with its old `touched` state. With `arrays()`, removed items stay gone and `"d"` gets a new key and fresh state.

## Rendering list-level errors

Validation rules that apply to the whole list (like *"Add at least one task"*) attach their errors to the array field itself rather than to any row. Subscribe to the array handle to display them next to the list:

```tsx framework=react
const errors = useField(tasks, (snapshot) => snapshot.shownErrors);
```

```tsx framework=solid
const list = createField(tasks); // read list.shownErrors
```
