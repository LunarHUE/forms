A mask cleans a field's value before the store takes it. Put `mask()` in the
form's plugins, and a `masked(...)` part on the field type it cleans:

```ts
const PhoneField = defineField(PhoneInput, masked({ clean: digits, display: formatPhone }));

const forms = createForms({ plugins: [mask()], fields: { PhoneField } });
```

Every field `<form.PhoneField>` renders gets the mask, and only those. Every
value that reaches the field goes through `clean` first, whether the user
typed it, a reset wrote it or another plugin did. `digits` and `upper` are
ready-made cleaners, and any function from string to string works.

`masked` fits string fields only, so `defineField(NumberInput, masked(...))` is a
type error. So is a form that renders `PhoneField` without `mask()` in its
plugins: the error reads `Add mask() to this form's plugins: PhoneField uses
it`.

## Display text

A cleaner changes what the store holds, not what the input shows. Give the
part a `display` to show the value formatted. With `formatPhone` above, the
input shows `(555) 123-4567` and the store, `field.value` and `onSubmit` get
`5551234567`.

`display` gets the clean value and returns the text to show. A value that
isn't a string reaches it as `""`. Keep it a pure function of the value, since
the server and the browser both call it. Text inputs and textareas show the
display text, on the server too, so the page hydrates with it. Number,
checkbox, radio and select inputs ignore it.

Everything except the input reads the stored value: `field.value`, the
schema, `onSubmit`, `dirty`, history and persistence. The display text lives
only in `field.text`, which `inputProps(field)` uses too. An input bound to
`field.value` instead shows the stored value. To keep the caret in place,
write with `field.setText(text, event)`. See
[Binding an element](../basics/fields#binding-an-element).

A plugin of your own can give a field display text too. See
[Writing a plugin](../writing-plugins/first-plugin#display-text-from-a-plugin).

## Fields that haven't rendered

A field type's parts attach the first time it renders a field, and the
field's value is cleaned then. A value that matters before that, such as a
field on a step the user hasn't reached, can be pinned on the definition:

```ts
const contact = forms.define({ defaultValues, onSubmit }, PhoneField.at("phone"));
```

The mask then attaches when the store is made. Rendering the field later
doesn't attach it twice.

## Caret

The caret stays where the user is typing. After typing or pasting it steps
over the characters the display adds, so typing carries on past a `-`. After a
backspace it doesn't, so the next backspace deletes a digit. A character
`clean` drops leaves the text and the caret as they were.

A field with only a cleaner shows the clean value. When the cleaner changes
the text, as `upper` does, React or Solid may move the caret to the end when
it rewrites the input. `{ clean: upper, display: (value) => value }` keeps it
in place.

## Two masks on one field

A field type can carry more than one `masked` part. Each cleans in turn, in
the order listed. If both give a display, the first one wins: the input shows
its text and keeps the caret with its `clean`.

## What gets cleaned

- A write above a field, such as `setValue` on `address`, a root replace from
  `bind`, or a row that `push` or `insert` adds, is cleaned at each masked
  field below it.
- The field's value is cleaned when the part attaches, and so is its baseline
  while the field isn't dirty, so the form doesn't start dirty and a reset
  leaves it clean.
- User edits, resets and other plugins' writes are cleaned. A value `persist`
  restores comes out clean.
- Rebases aren't. The incoming value is the server's copy, and the baseline
  moves to it as it came. Cleaning it would make the form dirty against its
  own baseline.
