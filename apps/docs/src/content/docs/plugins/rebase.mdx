The user is editing a record when a fresher copy arrives from the server.
Taking it whole loses their typing, and ignoring it leaves stale values in
the fields they didn't touch. `rebase` merges the two, field by field.

<Demo name="rebase/profile" />

Edit the name, then press Refresh. The name keeps your text and the email
takes the server's.

`form.plugins.rebase(handle, incoming, resolve)` moves the baseline of the
subtree at `handle` to `incoming`, such as a fresh copy from the server. A
leaf whose current value already equals the incoming one only moves its
baseline. For every other leaf, `resolve` picks what it becomes:

```ts
const fresh = await fetchProfile();
form.plugins.rebase(form.root, fresh, (leaf) => (leaf.edited ? "keep" : "take"));
```

- `"keep"` keeps the current value. The field stays dirty against the new
  baseline.
- `"take"` writes the incoming value.
- `{ value }` writes a value of your own, such as a merge of the two.

Each leaf comes with its `path`, the current `value`, the old `baseline`, the
`incoming` value and `edited`, true when the user has edited it.

## Keeping the focused field

A user who clicked into a field but hasn't typed yet has `edited` false, so
the resolve above writes the server's value under their cursor. Keep the
focused field too. `isFocused(handle)` is true while focus is on one of the
field's elements or inside one:

```ts framework=react
import { isFocused } from "@lunarhue/forms-react";

form.plugins.rebase(form.root, fresh, (leaf) => {
  const field = form.store.fieldAt(leaf.path);
  return leaf.edited || (field !== undefined && isFocused(field)) ? "keep" : "take";
});
```

```ts framework=solid
import { isFocused } from "@lunarhue/forms-solid";

form.plugins.rebase(form.root, fresh, (leaf) => {
  const field = form.store.fieldAt(leaf.path);
  return leaf.edited || (field !== undefined && isFocused(field)) ? "keep" : "take";
});
```

`isFocused` reads the elements the field's ref got, the ones `elementsOf`
lists, so it needs no setup in production. Checking
`fieldOf(document.activeElement)` instead works in development and then
finds nothing in production, unless the app called `trackElements()` before
the form rendered. It also misses an input inside a custom component, since
`fieldOf` doesn't look at ancestors.

A leaf is one value. A custom input on an object field, such as a date range
over `{ start, end }`, registers on the object, so check the leaf's parent:
`form.store.fieldAt(leaf.path.slice(0, -1))`.

## Rebase or reset

Rebase is for keeping edits. When the user's edits should go, as after a save
or when they pick a different record, reset the form to the new copy instead.
It needs no plugin:

```ts
const fresh = await fetchProfile();
form.store.reset({ values: fresh });
```

`reset({ values })` writes the values and makes them the baseline in one
step. It clears touched, edited and error state, and aborts a running submit,
as `reset()` does. With [`dirty()`](./dirty) the form is clean afterwards,
and a later `reset()` comes back to these values. `reset({ to: "initial" })`
still goes back to the values the form started with. `history` forgets its
steps, as on any reset.

Writing the values with `setValue` doesn't do this. It leaves the baseline
where it was, so the form stays dirty and `reset()` brings the old values
back.

## What it returns

`rebase` returns `{ taken }`, the paths it wrote with `"take"` or `{ value }`.
Validators that already ran on those fields run again. Listeners run
once, after the whole rebase.

Pass any handle of the form, such as `form.root.at("address")`, to rebase one
part of it. A handle from another form throws
[`rebase:store`](/errors#core:rebase:store).

## Comparing values

With [`dirty()`](./dirty) installed, rebase compares values with the form's
dirty comparison, including any `equals` you gave. Without it, values compare
by `Object.is`, so a date with the same time counts as changed and goes to
`resolve`.

Objects are walked key by key. An array is walked item by item when its items
still have the keys and order of its baseline and the incoming array is as
long. Otherwise the whole array is one leaf.

## Other plugins

Rebase writes aren't user edits. `history` records no step for them, and a
`masked` part doesn't clean them, since the incoming value is the server's
copy.
