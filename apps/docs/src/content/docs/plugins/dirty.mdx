Which fields did the user change? A Save button that stays disabled until
something changed, a "you have unsaved changes" prompt and a PATCH that sends
only the changed fields all need that answer. `dirty()` gives it. Change a
field, then change it back.

<Demo name="dirty/profile" />

With `dirty()` installed, each field and the form get `dirty`, true while the
value differs from its baseline. The baseline starts as the form's starting
value. Typing a field back to that value makes it clean again.

```tsx framework=react
import { dirty } from "@lunarhue/forms-react/plugins";

const forms = createForms({ plugins: [dirty()] });
```

```tsx framework=solid
import { dirty } from "@lunarhue/forms-solid/plugins";

const forms = createForms({ plugins: [dirty()] });
```

`form.store.changes()` lists the fields that differ, for event handlers and effects. An `equals` function on
`createForms` or a definition decides what counts as equal, as two dates with
the same time.

## Without it

Reading `dirty` on a form or field snapshot, calling `changes()` and giving
`equals` are type errors. The snapshots still carry `dirty: false` at runtime.
In development `changes()` throws
[`dirty:missing`](/errors#core:dirty:missing). In production it returns an
empty list.

A component that reads `dirty` from a field it is given says so in its type.
See [Components that need a plugin](../plugin-composition/components).

Core keeps the baseline either way, so a reset still goes back to it, and
`rebase` and `bind` still move it. [`rebase`](./rebase) then compares values
by `Object.is` alone.

## Clean after a save

Nothing moves the baseline when a save succeeds. A settings page that stays on
screen after saving stays dirty, and its Save button never disables again.
`baselineOnSubmit` fixes that. Import it from the same entry and put it on the
definition:

```tsx framework=react
import { baselineOnSubmit, dirty } from "@lunarhue/forms-react/plugins";

const forms = createForms({ plugins: [dirty()] });
const settings = forms.define({
  defaultValues,
  plugins: [baselineOnSubmit()],
  onSubmit: saveSettings,
});
```

```tsx framework=solid
import { baselineOnSubmit, dirty } from "@lunarhue/forms-solid/plugins";

const forms = createForms({ plugins: [dirty()] });
const settings = forms.define({
  defaultValues,
  plugins: [baselineOnSubmit()],
  onSubmit: saveSettings,
});
```

When a submit ends `"succeeded"`, the value `onSubmit` got as `ctx.input`
becomes the baseline. An invalid, refused or failed submit leaves the baseline
alone, and so does a submit that a reset stops. A save the server refuses
counts as invalid when `onSubmit` puts its errors on the form with
`setErrors`.

- A field the user edits while the save runs keeps the newer text and stays
  dirty. Typing the saved text back makes it clean.
- Array items pair by the keys they had when the value was sent. An item
  inserted, removed or moved during the save keeps its own dirty flag.
- Moving the baseline writes no value, so `history` records no step.
- Without `dirty()` nothing is dirty, but the baseline still moves, so a later
  reset goes back to the saved value.

You don't need it for a create form that navigates away after saving, for a
search form, or for an app that refetches after saving and passes the fresh
copy to `form.store.reset({ values })` or `rebase`.

The plugin trusts the value that was sent. When the server stores something
else, such as a trimmed name or a new `updatedAt`, bring its copy in with
[`rebase`](./rebase).
