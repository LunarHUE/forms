Validation is part of every form, and [Validation](../concepts/validation)
covers it. A schema plugin adapts one schema library, so a definition can take
`schema` from it. The schema checks the form and types it, and the plugin
works out the form's starting values from it.

## Zod and Valibot

`zod()` from `@lunarhue/forms-schema/zod` takes Zod 4 schemas, from `zod` or
`zod/mini`. `valibot()` from `@lunarhue/forms-schema/valibot` takes Valibot
schemas, sync or async. The library is an optional peer dependency, so install
only the one you use:

<Install packages="@lunarhue/forms-schema zod" />

```ts
import { zod } from "@lunarhue/forms-schema/zod";
import { z } from "zod";

const forms = createForms({ plugins: [zod()] });

const signUp = forms.define({
  schema: z.object({
    username: z.string().min(3, "Use at least 3 characters."),
    email: z.email("Enter a valid email."),
  }),
  onSubmit: (value) => value,
});
```

A Zod schema on a form with no `zod()` is a type error, and the message names
`zod()`. The same goes for Valibot.

## Starting values

The starting values come from the schema: strings start empty, booleans
false, arrays empty, and a declared `.default()` wins. A number or an enum has
no empty value, so it starts `undefined`. `defaultValues` is optional and
overrides any part of what the schema gives.

## Another library

`definePlugin` from `@lunarhue/forms-core/plugins` makes a schema plugin for
any [Standard Schema](https://standardschema.dev) library when you give it a
`name` and a `schema` adapter. Validation and types already go through
Standard Schema, so the adapter only says which schemas it accepts and what
values they start from. It has:

- `vendor`: the library's name, matched against `schema["~standard"].vendor`.
- `defaultValue(schema)`: the value a form starts from when `defaultValues`
  leaves it out.
- `itemValue(schema, path)`: the value `push` or `insert` gives a new item of
  the array at `path` when it gets none.

```ts
import type { SchemaAdapter } from "@lunarhue/forms-core";
import { definePlugin } from "@lunarhue/forms-core/plugins";
import { defaultOf, itemDefaultOf, type ArkSchema } from "./ark-defaults";

const adapter: SchemaAdapter<ArkSchema> = {
  vendor: "arktype",
  defaultValue: (schema) => defaultOf(schema),
  itemValue: (schema, path) => itemDefaultOf(schema, path),
};

export const ark = () => definePlugin({ name: "ark", schema: adapter });
```

With `ark()` in a form's plugins, `defaultValues` becomes optional for an
`ArkSchema`. Without it, `defaultValues` is required and complete. `zod()` and
`valibot()` are schema plugins of the same shape.

## A helper generic over the schema

A helper that takes any schema and returns a definition fails with TS2353
when its type parameter is the schema type. Make it generic over the schema's
values instead. [Writing a plugin](writing-a-plugin#ts2353-from-define-in-a-function-generic-over-the-schema)
explains why and has both fixes.

## Where plugins come from

Every plugin goes in a `plugins` list: on `createForms` for every form, on a
definition for its forms, or on one form.

```tsx framework=react
const form = useForm(signUp, { plugins: [persist("sign-up")] });
```

```tsx framework=solid
const form = createForm(signUp, { plugins: [persist("sign-up")] });
```

A form's own list is read once, when the form is made, and its plugins run
after the others.

| Kind        | Needs another library | Import from                                         |
| ----------- | --------------------- | --------------------------------------------------- |
| First class | No                    | your adapter, `<adapter>/plugins`                   |
| Third party | Yes                   | its package, such as `@lunarhue/forms-schema/zod`   |
| Community   | Up to the author      | the author's package, named `forms-plugin-<name>`   |

First-class plugins live in `@lunarhue/forms-core/plugins`, and each adapter
re-exports them from its own `plugins` entry. Your bundler keeps only the ones
you import. `history`, `mask`, `rules`, `persist`, `rebase` and `dirty` are first
class, and each has a page in this section. To make your own, see
[Writing a plugin](writing-a-plugin).
