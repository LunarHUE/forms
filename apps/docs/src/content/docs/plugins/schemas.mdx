You can already [validate with any Standard Schema](../basics/schema-validation) with no plugin installed. The catch is that Standard Schema only exposes a `validate` function and TypeScript types, so core can't inspect your schema's fields to infer starting values.

Schema plugins fill that gap. Because a schema plugin understands Zod or Valibot directly, it can walk your schema and generate starting values automatically, letting you omit `defaultValues` completely, just like the demo below.

## Installing Zod or Valibot support

`@lunarhue/forms-schema/zod` supports Zod 4 (both `zod` and `zod/mini`), and `@lunarhue/forms-schema/valibot` supports Valibot (sync and async). Both schema libraries are optional peer dependencies, so install only the one you use:

<Install packages="@lunarhue/forms-schema zod" />

```ts
import { zod } from "@lunarhue/forms-schema/zod";
import { z } from "zod";

const forms = createForms({ plugins: [zod()] });

const signUp = forms.define({
  schema: z.object({
    name: z.string().min(1, "Enter your name."),
    age: z.number("Enter your age.").int().min(18, "You must be 18 or over."),
    plan: z.enum(["free", "pro"]).default("free"),
    newsletter: z.boolean(),
  }),
  onSubmit: (value) => value,
});
```

## How default values are generated

The plugin derives starting values straight from your schema:
- **Strings** start as `""`, **booleans** as `false`, and **arrays** as `[]`.
- Any explicit `.default(...)` in your schema wins.
- **Numbers** and **enums** have no obvious empty value, so they start as `undefined`.

`defaultValues` becomes optional. If you do pass it, anything you specify overrides the schema-generated defaults.

If a form uses a schema from a library without an installed plugin, validation still works via Standard Schema; you just provide complete `defaultValues` as shown in Basics.

## What's planned next

Schema plugins are also the foundation for pulling field constraints (like `min`, `max`, and `maxLength`) directly from your schema into inputs so you don't have to repeat them in JSX.

## Writing a generic helper around `define`

If you write a helper function that accepts *any* schema and calls `forms.define({ schema })`, making the function generic over the schema type itself can trigger a `TS2353` error. Make it generic over the schema's value type instead. [Writing a schema adapter](../writing-plugins/schema-adapters#ts2353-from-define-in-a-function-generic-over-the-schema) explains why and shows both patterns.

## Adding another schema library

Want the same automatic defaults for ArkType or another Standard Schema library? You can build a custom schema plugin using the `schema` adapter hook. See [Schema adapters](../writing-plugins/schema-adapters).
