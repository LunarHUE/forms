In real forms, fields often depend on each other: disable the street address when "Store pickup" is checked, or hide the gift message unless "Include a gift note" is enabled. The `rules()` plugin computes `disabled` and `hidden` flags straight from the form's values, updating in the same render as the change.

## Defining rules on a form

Install `rules()` in your form's `plugins`, then pass a `ruled(...)` part right after the config object in `forms.define()`. Map each dotted field name to a function that inspects the form value and returns `{ disabled?, hidden? }` (any flag you omit is left unchanged):

```ts
const forms = createForms({ plugins: [rules()], fields });

const order = forms.define(
  { defaultValues: { pickup: false, gift: false, street: "", message: "" } },
  ruled({
    street: (value) => ({ disabled: value.pickup }),
    message: (value) => ({ hidden: !value.gift }),
  }),
);
```

`ruled` infers the form's value type straight from `define`, so `value` is typed and a typo like `"stret"` fails at compile time. Forgetting to include `rules()` in `plugins` is also caught by TypeScript.

Rules evaluate once when the part attaches and again after every batch that writes a value, before listeners fire, so there is never an extra render. Disabling a parent object (like `address`) automatically disables every field underneath it.

Because dotted names stop at arrays, rules target fields and objects rather than individual array items (you can still put a rule on the array itself or its parent object).

## Attaching rules to a fieldset

Reusable fieldsets can carry their own rules so they travel with the UI everywhere it's used. See [Parts on fieldsets](../plugin-composition/fieldset-parts).

## Reading `disabled` and `hidden` in components

`disabled` is a built-in field flag, so `inputProps(field)` forwards it to the DOM automatically. `hidden` lives in `rules`'s plugin meta, leaving your component in control of how hiding renders (omitting the element, collapsing a panel, and so on):

```tsx framework=react
function TextField({ field, label }: TextFieldProps) {
  if (rules.meta(field).hidden) return null;
  // ...
}
```

```tsx framework=solid
function TextField(props: TextFieldProps) {
  return (
    <Show when={!rules.meta(props.field).hidden}>
      {/* ... */}
    </Show>
  );
}
```

Fields without a `hidden` rule default to `{ hidden: false }`, so `rules.meta(field)` is always safe to read without null checks.

## Server rendering

Any flags computed before the store has listeners become part of its initial state, so fields hidden or disabled by rules render that way on the server and hydrate with no layout shift.
