Put `rules()` in the form's plugins, and a `ruled(...)` part after the
definition's config. `ruled` takes a map from a field's dotted name, the same
name a `name` prop takes, to a rule. Each rule gets the form value and returns
the field's `disabled` and `hidden` flags. A flag the rule leaves out stays as
it is.

```ts
const forms = createForms({ plugins: [rules()], fields });

const order = forms.define(
  { defaultValues: { pickup: false, gift: false, street: "", message: "" } },
  ruled({
    street: (value) => ({ disabled: value.pickup }),
    message: (value) => ({ hidden: !value.gift }),
  }),
);
```

`ruled` takes its value type from the definition, so `value` is typed and a
name that isn't a field, such as `"stret"`, is a type error. A form without
`rules()` in its plugins is a type error too.

Rules run when the part attaches and after every batch that writes a value,
before listeners, so the flags change in the same render as the value.
Disabling an object, such as `address`, disables every field below it.

Names go through objects only, so a rule can't name an array item. Give the
array a rule, or the object around it.

## Rules on a fieldset

A fieldset can carry rules of its own. Its rules get the fieldset's value,
not the form's, and name fields below it:

```ts
const Billing = forms.fieldset(BillingSchema, ruled({ address: (billing) => ({ hidden: billing.sameAsShipping }) }));
```

They attach at each field the fieldset is used on, the first time its scope
is read. A rule that matters before that can be pinned on the definition, as
`forms.define(config, Billing.at("billing"))`.

To write rules apart from the definition, name the value type:
`ruled<Order>({ ... })`.

## Disabled and hidden

`disabled` is a field flag, and `inputProps(field)` puts it on the input. `hidden`
is the plugin's own meta, so your component reads it and decides what hiding
means:

```tsx framework=react
function TextField({ field, label }: TextFieldProps) {
  if (rules.meta(field).hidden) return null;
  // ...
}
```

```tsx framework=solid
function TextField(props: TextFieldProps) {
  return (
    <Show when={!rules.meta(props.field).hidden}>
      {/* ... */}
    </Show>
  );
}
```

A field no rule hides reads `{ hidden: false }`, so the reader never returns
undefined.

## Server rendering

What the rules set before the store has listeners is part of its starting
state. A field a rule disables or hides renders that way on the server and
hydrates with no second render.
