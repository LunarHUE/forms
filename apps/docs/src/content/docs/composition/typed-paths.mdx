Every `name` prop is checked against the form's value type. A typo, or a
field the component can't edit, fails the build. For the parts of a form you
pass around, use a handle: a typed object for one field.

<Demo name="typed-paths/order" />

## Names

A name is a dotted path through the value, such as `"shipping.city"`. With
the order form above, a typo gets this:

```tsx framework=react
<form.TextField name="shipping.cty" label="City" />
```

```tsx framework=solid
<form.TextField name="shipping.cty" label="City" />
```

```text
error TS2769: No overload matches this call.
  ...
    Type '"shipping.cty"' is not assignable to type '"name" | "billing.street"
    | "billing.city" | "shipping.street" | "shipping.city"'.
    Did you mean '"shipping.city"'?
```

The list holds only the names `TextField` can edit. `shipping` is a name too,
but its value is an object and `TextField` takes a `FieldApi<string>`, so it
isn't offered.

Names go through objects and stop at arrays. `tasks` names the array, but
there is no `tasks.0.title`. Rows are reached through
handles, see [Arrays](../plugins/arrays). A name has at most 8 segments.

## Handles

`form.root` is the handle of the whole value. `at(key)` returns a child's
handle, typed from the value, and also catches typos:

```ts
const shipping = form.root.at("shipping"); // handle to { street, city }
const city = shipping.at("city"); // handle to a string

form.root.at("shiping");
// Argument of type '"shiping"' is not assignable to parameter of type
// '"name" | "billing" | "shipping"'.
```

A handle holds no state. It is the same object on every call, it carries the
field's commands (`setValue`, `reset`, `validate`, `push` on arrays and so
on), and `peek()` reads the current snapshot in event handlers. Pass one as
`handle` instead of `name`:

```tsx framework=react
<form.TextField handle={form.root.at("shipping").at("city")} label="City" />
```

```tsx framework=solid
<form.TextField handle={form.root.at("shipping").at("city")} label="City" />
```

<Only framework="react">

To render something from a handle's state, read it with `useField(handle)`,
or `useField(handle, select)` to re-render only when the selected part
changes.

</Only>

<Only framework="solid">

To render something from a handle's state, read it with
`createField(handle)`. Its members are reactive.

</Only>

## Fieldsets

A component that renders part of a form takes a handle prop. To type it,
make a fieldset from the part's schema and use `HandleOf`:

```tsx framework=react
import type { HandleOf } from "@lunarhue/forms-react";

const AddressFieldset = forms.fieldset(Address);

function AddressFields({ field }: { field: HandleOf<typeof AddressFieldset> }) {
  const scope = AddressFieldset.scope(field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField name="city" label="City" />
    </fieldset>
  );
}

<AddressFields field={form.root.at("shipping")} />;
```

```tsx framework=solid
import type { HandleOf } from "@lunarhue/forms-solid";

const AddressFieldset = forms.fieldset(Address);

function AddressFields(props: { field: HandleOf<typeof AddressFieldset> }) {
  const scope = AddressFieldset.scope(props.field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField name="city" label="City" />
    </fieldset>
  );
}

<AddressFields field={form.root.at("shipping")} />;
```

`scope(handle)` returns the same members a form has, `Field`, `Items` and
your registered components, with names relative to the handle. It is a cached
lookup, not a hook, so call it anywhere.

The fieldset's schema only types the shape. The form's own schema does the
validating. Without a schema, write the type: `forms.fieldset<Address>()`.

A handle fits when its value has exactly the shape: an array row, or a field
of another form from the same `createForms`. A handle of an object with more
keys doesn't. The component could replace the whole value and drop the keys
it doesn't know, so handles are strict in their value type. A handle of a
form with more plugins still fits one that asks for fewer.

To take objects with more keys, make the component generic in the value and
pass it as the second argument of `HandleOf`:

```tsx framework=react
function AddressFields<A extends Address>({ field }: { field: HandleOf<typeof AddressFieldset, A> }) {
  const scope = AddressFieldset.scope(field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField handle={field.at("city")} label="City" />
    </fieldset>
  );
}

// `office` has a `phone` too.
<AddressFields field={form.root.at("office")} />;
```

```tsx framework=solid
function AddressFields<A extends Address>(props: { field: HandleOf<typeof AddressFieldset, A> }) {
  const scope = AddressFieldset.scope(props.field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField handle={props.field.at("city")} label="City" />
    </fieldset>
  );
}

// `office` has a `phone` too.
<AddressFields field={form.root.at("office")} />;
```

A child that `Address` names, such as `field.at("city")`, reads as its type
in `Address`, so it fits a `FieldApi<string>` component. A child that is an
object itself stays generic and needs a generic component of its own. A
merge write such as `field.setValue({ city: "Oslo" })` doesn't type-check on
a generic handle. Write the child instead: `field.at("city").setValue("Oslo")`.

<Only framework="react">

`useInputProps` reads the value type from the handle's own type, so type the
child first: `const city: FieldHandle<string> = field.at("city")`.

</Only>

<Only framework="solid">

`createInputProps` reads the value type from the handle's own type, so type
the child first: `const city: FieldHandle<string> = props.field.at("city")`.

</Only>

A reusable list works the same way. It is generic in the item type and takes
a function that makes a full item, since it can't build the keys it doesn't
know:

```tsx
function TagList<T extends Tag>(props: {
  tags: ArrayHandle<T[], FormError, "arrays">;
  create: (base: Tag) => T;
}) {
  return (
    <>
      <Items handle={props.tags}>{(tag) => <TagFields field={tag} />}</Items>
      <button type="button" onClick={() => props.tags.push(props.create({ id: Date.now(), name: "" }))}>
        Add
      </button>
    </>
  );
}

<TagList tags={form.root.at("tags")} create={(base) => ({ ...base, enabled: true })} />;
```
