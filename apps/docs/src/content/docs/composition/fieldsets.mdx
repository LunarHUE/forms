In the demo below, a single `AddressFields` component renders both the shipping and billing addresses. You hand it a field handle, and all of its field names are scoped relative to that handle—so it works on any form that contains an address.

## Creating a fieldset and typing the handle

Start by creating a fieldset with `forms.fieldset(Schema)` (or `forms.fieldset<Address>()` if you're not using a schema), then type your component's `field` prop with `HandleOf<typeof AddressFieldset>`:

```tsx framework=react
import type { HandleOf } from "@lunarhue/forms-react";

const AddressFieldset = forms.fieldset(Address);

interface AddressFieldsProps {
  field: HandleOf<typeof AddressFieldset>;
}

function AddressFields({ field }: AddressFieldsProps) {
  const scope = AddressFieldset.scope(field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField name="city" label="City" />
    </fieldset>
  );
}

<AddressFields field={form.root.at("shipping")} />;
```

```tsx framework=solid
import type { HandleOf } from "@lunarhue/forms-solid";

const AddressFieldset = forms.fieldset(Address);

interface AddressFieldsProps {
  field: HandleOf<typeof AddressFieldset>;
}

function AddressFields(props: AddressFieldsProps) {
  const scope = AddressFieldset.scope(props.field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField name="city" label="City" />
    </fieldset>
  );
}

<AddressFields field={form.root.at("shipping")} />;
```

## How scopes work

`AddressFieldset.scope(handle)` returns the same component helpers you get on a form—`Field`, `Items`, and all of your registered field components—with every `name` resolved relative to `handle`. It's a cached lookup rather than a hook, so you can call it anywhere without hook-order restrictions.

Note that passing a schema to `forms.fieldset(Address)` is only for typing the shape—the form's own schema still handles validation.

## Why handles check exact shapes

Any handle with the exact `Address` shape fits `AddressFields`—whether it's a nested object on another form from the same `createForms`, or a row inside an array.

A handle for an object with *extra* keys (say, `Address & { phone: string }`) won't fit by default. Because a handle can call `setValue` to replace the entire object, allowing a narrower type could accidentally wipe out keys the component doesn't know about. (Plugins are the opposite: a handle from a form with *more* plugins always fits a fieldset that asks for fewer.)

## Accepting extra keys with generic fieldsets

If you want `AddressFields` to work on any object that *extends* `Address` (like an office address that also has a `phone` field), make the component generic and pass the type parameter as the second argument to `HandleOf`:

```tsx framework=react
interface AddressFieldsProps<A extends Address> {
  field: HandleOf<typeof AddressFieldset, A>;
}

function AddressFields<A extends Address>({ field }: AddressFieldsProps<A>) {
  const scope = AddressFieldset.scope(field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField handle={field.at("city")} label="City" />
    </fieldset>
  );
}

// `office` has a `phone` too.
<AddressFields field={form.root.at("office")} />;
```

```tsx framework=solid
interface AddressFieldsProps<A extends Address> {
  field: HandleOf<typeof AddressFieldset, A>;
}

function AddressFields<A extends Address>(props: AddressFieldsProps<A>) {
  const scope = AddressFieldset.scope(props.field);
  return (
    <fieldset>
      <scope.TextField name="street" label="Street" />
      <scope.TextField handle={props.field.at("city")} label="City" />
    </fieldset>
  );
}

// `office` has a `phone` too.
<AddressFields field={form.root.at("office")} />;
```

Any primitive child defined on `Address` (like `field.at("city")`) resolves to its known type, so it plugs straight into a `FieldApi<string>` component. Nested object children stay generic and should be handed to their own generic fieldset. You also can't call `field.setValue({ city: "Oslo" })` directly on a generic handle—write to the child handle instead (`field.at("city").setValue("Oslo")`).

<Only framework="react">

When calling `useField` on a child of a generic handle, annotate the child handle first (`const city: FieldHandle<string> = field.at("city")`) so `useField(city)` infers `string` cleanly before you pass it to `inputProps`.

</Only>

When calling `createField` on a child of a generic handle, annotate the child handle first (`const city: FieldHandle<string> = props.field.at("city")`) so `createField(city)` infers `string` cleanly before you pass it to `inputProps`.
