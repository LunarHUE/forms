A validator that returns a promise is async. Try `ada` as the username.

<Demo name="async-validation/username" />

```ts
const account = forms.define({
  defaultValues: { username: "" },
  validate: {
    fields: fieldValidators({
      username: validateOn(
        debounced(
          async (name, { signal }) =>
            (await isTaken(name, signal)) ? { message: "That name is taken." } : undefined,
          400,
        ),
        "input",
      ),
    }),
  },
  show: "always",
});
```

`debounced(check, ms)` waits for a pause in typing before it calls `check`, and
`validateOn(check, "input")` runs it from the first keystroke instead of the
first blur. Both return a validator, so they nest, and they work in a
`validate` prop too. Errors show once the field is blurred by default, so
`show: "always"` lets the answer appear while the user is still typing. See
[Showing errors](./validation#showing-errors).

## Newer runs win

When the user types again, the older run's `signal` aborts and its result is
dropped, so a slow answer never wins over a newer one. Pass the signal to
`fetch`. It also aborts when the field is reset or the validator is removed.

## While it runs

`field.validating` is true while a validator on the field runs, and the form
state's `validating` while any does. Show it next to the input:

```tsx
<form.Field name="username">
  {(field) => (
    <>
      <input {...inputProps(field)} />
      {field.validating ? <p role="status">Checking...</p> : null}
    </>
  )}
</form.Field>
```

## On submit

A submit skips the debounce. It waits for a check that is still running and
goes on only if it passed. A check whose result is still current doesn't run
again. Wrap the check in `recheckOnSubmit(check)` to run it on every submit
anyway, as for a check that can go stale:

```ts
username: recheckOnSubmit(validateOn(debounced(checkName, 400), "input")),
```
