Not every form mounts once and unmounts right after submit. Think of a master-detail screen where the user clicks from one customer to the next, or a payment form whose parent passes in a changing account balance or `onSave` callback.

<Only framework="react">

`useForm` only reads its arguments on the initial render. If props change on a later render—a different record, a new limit, or a fresh callback—the existing form instance won't recreate itself. Here's how to handle each case cleanly.

## Switching between records

The simplest and cleanest way to switch records is to give your form component a `key` tied to the record's ID. When the key changes, React mounts a fresh component and initializes a brand-new form with the new record's values:

```tsx
const customerForm = forms.define((saved: Customer) => ({
  defaultValues: saved,
  onSubmit: (value) => customers.save(value),
}));

function CustomerPane({ customer }: { readonly customer: Customer }) {
  return <CustomerForm key={customer.id} saved={customer} />;
}

function CustomerForm({ saved }: { readonly saved: Customer }) {
  const form = useForm(customerForm, saved);
  // ...
}
```

Any unsaved edits from the previous record are discarded along with the old form. On the other hand, if you're receiving an updated copy of the *same* record (like a background refetch), keep the same `key` and [rebase](../plugins/rebase) the form onto the fresh data so the user doesn't lose what they're typing.

## Validating against live props

Because form definitions live outside your component, they can't close over React props. Instead, attach prop-dependent rules inside the component using `useValidator` or the `validate` prop—both always invoke the latest function from the current render:

```tsx
function TransferForm({ balance }: { readonly balance: number }) {
  const form = useForm(transferForm);
  useValidator(form.root.at("amount"), (amount) =>
    amount > balance ? { message: "That's more than the balance." } : undefined,
  );
  // ...
}
```

Choose where to register the validator based on how long it should stay active:

- **On a field component** (`form.Field`'s `validate` prop or `useValidator` on a field handle): active only while that field is mounted. Good for conditional UI, though a hidden wizard step won't block submit.
- **On the form root** (`useValidator(form.root, check)`): active for the entire lifetime of the form. `check` receives the whole form value, so it can compare multiple fields against props at once. Its errors land on the root, so make sure you render root errors.

Note that a prop change by itself doesn't automatically re-run validation. If you want an error to appear or clear the instant `balance` changes, kick off `validate()` in an effect:

```tsx
const amount = form.root.at("amount");
useEffect(() => {
  void amount.validate();
}, [amount, balance]);
```

## Calling the latest prop callback on submit

When you use the function form of `forms.define((input) => ...)`, `useForm` only passes `input` once on mount—so a callback passed directly through `input` would capture stale closures from that first render.

If the callback is something that happens *after* a successful save (like closing a modal or showing a toast), you don't need to pass it into the definition at all. Just await `form.submit()` in your component's submit handler, where you always have the latest props:

```tsx
async function save(event: FormEvent) {
  event.preventDefault();
  const submission = await form.submit();
  if (submission.status === "succeeded") onSaved(submission.result);
}

<form {...form.formProps} onSubmit={(event) => void save(event)}>
```

If `onSubmit` itself needs a changing callback prop (such as a parent-provided `onSave` function), keep the latest callback in a ref and pass a stable wrapper into `useForm`:

```tsx
const customerForm = forms.define((input: { saved: Customer; save: (value: Customer) => Promise<void> }) => ({
  defaultValues: input.saved,
  onSubmit: (value) => input.save(value),
}));

function CustomerForm({ saved, onSave }: CustomerFormProps) {
  const latest = useRef(onSave);
  useEffect(() => {
    latest.current = onSave;
  });
  const form = useForm(customerForm, { saved, save: (value) => latest.current(value) });
  // ...
}
```

Why a ref instead of React 19.2's `useEffectEvent`? React only permits calling `useEffectEvent` functions from inside effects, whereas a form submit runs from an event handler. A plain ref works reliably everywhere.

<Only framework="solid">

`createForm` runs once when your component initializes. Because Solid props are reactive getters, any callback that reads `props.something` when invoked automatically sees the latest value—which makes prop-dependent validators and submit callbacks effortless. Only switching between records needs a fresh form instance.

## Switching between records

Wrap your form component in a keyed `<Show>` so Solid creates a fresh component (and form) whenever the record changes:

```tsx
const customerForm = forms.define((saved: Customer) => ({
  defaultValues: saved,
  onSubmit: (value) => customers.save(value),
}));

function CustomerPane(props: { readonly customer: Customer }) {
  return (
    <Show when={props.customer} keyed>
      {(customer) => <CustomerForm saved={customer} />}
    </Show>
  );
}
```

Unsaved edits from the previous record are discarded with the old form. Keep in mind that a refetched copy of the *same* record is a new object reference too—if you want to absorb a fresh server copy without wiping the user's typing, keep the `<Show>` value stable and [rebase](../plugins/rebase) the form instead.

## Validating against live props

Since form definitions live outside components, attach prop-dependent rules inside your component with `createValidator` or the `validate` prop. Reading `props.balance` inside the check always sees the latest value:

```tsx
function TransferForm(props: { readonly balance: number }) {
  const form = createForm(transferForm);
  createValidator(form.root.at("amount"), (amount) =>
    amount > props.balance ? { message: "That's more than the balance." } : undefined,
  );
  // ...
}
```

Using `createValidator` on a field handle (or `form.Field`'s `validate` prop) ties the rule to that field's lifetime. Registering it on `form.root` in the form component keeps it active for the whole form, gives it the full form value, and puts its errors on the root.

A prop update alone doesn't trigger revalidation. If the error should update immediately when `props.balance` changes, call `form.root.at("amount").validate()` inside an effect that tracks `props.balance`.

## Calling the latest prop callback on submit

Pass a small wrapper function that reads `props.onSave` at call time, and your definition will always invoke the parent's latest callback:

```tsx
const customerForm = forms.define((input: { saved: Customer; save: (value: Customer) => Promise<void> }) => ({
  defaultValues: input.saved,
  onSubmit: (value) => input.save(value),
}));

function CustomerForm(props: CustomerFormProps) {
  const form = createForm(customerForm, { saved: props.saved, save: (value) => props.onSave(value) });
  // ...
}
```
