Every time you render `<form.Field name="...">`, it passes a field object to your render function with that field's state, commands, and DOM bindings. From there, a helper like `inputProps` or `numberProps` turns it into the props an HTML element expects.

Try typing a number with a trailing `.` in the Age input below and watch how the stored value behaves underneath.

<Demo name="fields/profile" />

```tsx
<form.Field name="age">
  {(field) => <input {...numberProps(field)} />}
</form.Field>
```

## Inside the field object

`FieldApi<T>` bundles a field's state, commands, and element bindings into one object, returning a fresh object whenever the field changes.

| Member | What it is |
| --- | --- |
| `value` | The current value stored for this field. |
| `name` | Dotted path with array indexes, like `tasks.0.title`. |
| `errors`, `shownErrors` | All active errors, and the subset allowed through by your `show` setting. |
| `userErrors` | Errors set manually via `setErrors` (these also appear at the end of `errors`). |
| `touched`, `edited`, `dirty` | Whether the field has been blurred, changed by the user, or differs from its baseline (`dirty` requires the `dirty()` plugin). |
| `invalid`, `validating` | Whether the field has any errors, and whether an async validator is currently running. |
| `disabled`, `readOnly` | Inherited from this field or any parent field above it. |
| `setValue`, `setTouched`, `setErrors`, `handleBlur`, `reset`, `validate` | Field commands. Array fields also include `push`, `insert`, `remove`, and `move`. |
| `text`, `setText`, `ref` | Low-level bindings for custom inputs and component libraries (see below). |
| `handle` | The stable field handle, useful to pass to child components or keep for later. |
| `id`, `errorId` | Stable DOM IDs for the input and its error container. |

## Props helpers for plain HTML

For standard HTML controls, use one of the standalone props helpers. Each helper wires up `name`, `id`, value, change and blur handlers, `ref`, `disabled`, `readOnly`, and ARIA attributes (`aria-invalid` and `aria-describedby` while errors show).

Because they are standalone functions rather than methods on `field`, your bundler drops any you don't import. Each helper is also strictly typed to the value type it writes:

| Helper | Element | Expected field type |
| --- | --- | --- |
| `inputProps(field)` or `inputProps(field, { type: "email" })` | `<input>` | `string` |
| `textareaProps(field)` | `<textarea>` | `string` |
| `selectProps(field)` | `<select>` | `string` |
| `numberProps(field)` | `<input type="number">` | `number` |
| `rangeProps(field)` | `<input type="range">` | `number` |
| `checkboxProps(field)` | `<input type="checkbox">` | `boolean` |
| `checkboxGroupProps(field, value)` | one checkbox in a group | `string[]` or `number[]` |
| `radioProps(field, value)` | one radio button | `string`, `number`, or `boolean` |

For `numberProps` and `selectProps`, pass an `empty` option to choose what gets written when the input is cleared (e.g., `numberProps(field, { empty: 0 })`). It defaults to `undefined`, and TypeScript requires it whenever your field's type doesn't allow `undefined`.

<Only framework="react">

If a component receives a `handle` instead of a `field` object, read the field with `useField(handle)` and pass it in: `inputProps(useField(handle))`. For custom inputs that only need to register their DOM element, use `useFieldRef(handle)`.

</Only>

<Only framework="solid">

Every helper also accepts a `describedBy` option for extra hint IDs that should appear in `aria-describedby` ahead of the error ID (for radios and checkbox groups, pass it as the third argument):

```tsx framework=solid
<input {...inputProps(field, { type: "email", describedBy: "email-hint" })} />
<input {...radioProps(field, "pro", { describedBy: "plan-hint" })} />
```

The returned value, `name`, flags, and ARIA attributes are reactive getters, so Solid updates each DOM attribute independently.

If a component receives a `handle` instead of a `field`, create the field object with `createField(handle)` (`inputProps(createField(handle))`), or register a custom element with `fieldRef(handle)`.

</Only>

## How number inputs work

Typing a number isn't always valid mid-keystroke; strings like `12.` or `-` are in-progress edits. `numberProps(field)` (and `numberPieces(field)` for custom inputs) keeps the raw text in the input while storing a real `number` (or `undefined`) in the form:

| User types | Input displays | Store holds |
| --- | --- | --- |
| `12.` | `12.` | `12` |
| `-` | `-` | previous value |
| *(cleared)* | *(empty)* | `undefined`, or your `empty` option |

As long as the store still holds the value that text produced, the input keeps showing what the user typed so the caret and decimal point don't jump around. On blur, or if something else writes a new value, the display returns to the formatted number.

## Optional fields

Optional properties like `nickname?: string` start as `undefined`. Props helpers render `undefined` as an empty string (or unchecked for checkboxes). Because `defaultValues` can't omit a key and still tell TypeScript it exists, pass the type parameter explicitly on `define<T>()`:

```ts
interface Profile {
  name: string;
  nickname?: string;
}

const profile = forms.define<Profile>({ defaultValues: { name: "" } });
```

## Extracting a field component

You can pass `field` from `form.Field` directly into your own component typed with `FieldApi<T>`:

```tsx framework=react
import { type FieldApi, inputProps } from "@lunarhue/forms-react";

interface TextInputProps {
  field: FieldApi<string>;
  label: string;
}

function TextInput({ field, label }: TextInputProps) {
  return (
    <label>
      {label}
      <input {...inputProps(field)} />
    </label>
  );
}

<form.Field name="name">{(field) => <TextInput field={field} label="Name" />}</form.Field>;
```

```tsx framework=solid
import { type FieldApi, inputProps } from "@lunarhue/forms-solid";

interface TextInputProps {
  field: FieldApi<string>;
  label: string;
}

function TextInput(props: TextInputProps) {
  return (
    <label>
      {props.label}
      <input {...inputProps(props.field)} />
    </label>
  );
}

<form.Field name="name">{(field) => <TextInput field={field} label="Name" />}</form.Field>;
```

<Only framework="solid">

Always access `props.field` rather than destructuring `field` out of `props`, otherwise Solid reads each property once and stops tracking updates.

</Only>

Once you're using `TextInput` everywhere, register it on `createForms` so you can write `<form.TextInput name="name" label="Name" />` with no wrapper. See [Reusable field components](../composition/field-components).

## Binding UI component libraries

Primitive libraries like Base UI, Radix, and React Aria already manage their own labels, IDs, and ARIA wiring, and expose a value plus change callback API. Instead of `inputProps`, pass them the four low-level pieces directly from `field`:

| Piece | Role |
| --- | --- |
| `text` | The string to display, including formatting from parts like masks, falling back to the field's value. |
| `setText(text, from?)` | Writes typed text. With a mask, it also updates the formatted string and preserves caret position. Pass the element or event as `from` (if omitted, it uses the focused element tracked by `ref`). |
| `handleBlur` | Marks the field touched and runs blur validation. |
| `ref` | Registers the element so invalid submits can focus it automatically. |

For custom numeric inputs, `numberPieces(field)` returns a matching `{ text, setText, handleBlur }` that handles in-progress strings like `-` and `12.` (and accepts `{ empty }` just like `numberProps`).

For non-text controls like checkboxes, switches, selects, and radio groups, bind `field.value` and `field.setValue` directly.

```tsx framework=react
const { ref } = field;

<Input
  ref={ref}
  value={field.text}
  onValueChange={(text, details) => field.setText(text, details.event)}
  onBlur={field.handleBlur}
/>

<Checkbox.Root ref={ref} checked={field.value} onCheckedChange={(checked) => field.setValue(checked)} />

const number = numberPieces(field);

<Input ref={ref} value={number.text} onValueChange={(text) => number.setText(text)} onBlur={number.handleBlur} />
```

<Only framework="react">

**React Compiler tip:** Pull `ref` out of `field` (`const { ref } = field`) or get it from `useFieldRef(handle)` before passing it to JSX `ref={...}`. Passing `ref={field.ref}` directly in a component body makes React Compiler treat the whole `field` object as a ref and skip optimizing the component. Inside a `<form.Field>` render callback, `ref={field.ref}` is fine because the compiler doesn't treat callbacks as render code.

</Only>

```tsx framework=solid
<input
  ref={field.ref}
  value={field.text}
  onInput={(event) => field.setText(event.currentTarget.value, event)}
  onBlur={field.handleBlur}
/>

<input
  type="checkbox"
  ref={field.ref}
  checked={field.value}
  onChange={(event) => field.setValue(event.currentTarget.checked)}
/>

const number = numberPieces(field);

<input
  ref={field.ref}
  value={number.text}
  onInput={(event) => number.setText(event.currentTarget.value)}
  onBlur={number.handleBlur}
/>
```

Primitives bound this way reflect `reset()` and restored values from `persist` automatically, since they always read `text` or `value`. If a primitive manages its own internal text buffer (like Base UI's `NumberField`), bind `field.value` and its numeric change callback instead of `text`.

React-managed primitives like Base UI's checkbox already stay in sync via props.

## Stable IDs and accessibility

Every field gets two stable IDs:

- **`field.id`** combines the form's ID with the field's stable path. It never changes over the life of the field, even when array rows move, so it works for both `<label htmlFor={field.id}>` and list keys.
- **`field.errorId`** is the ID to put on your error message element. Props helpers automatically point `aria-describedby` at `field.errorId` while errors show so screen readers announce them alongside the input. (If a primitive library renders its own error element, let it manage that linkage.)

<Only framework="react">

The form ID comes from React's `useId`, keeping server and client IDs identical. If you do SSR on React 16 or 17 (which don't have `useId`), pass an explicit `id` option to `useForm`. See [`id:server`](/errors#react:id:server).

</Only>
