`form.Field` takes a field name and passes that field's object to its child.
The object holds the field's state and commands, and a props function such
as `inputProps` turns it into the props an input needs. Type a number with a
trailing `.` and watch the line under Age.

<Demo name="fields/profile" />

```tsx
<form.Field name="age">
  {(field) => <input {...numberProps(field)} />}
</form.Field>
```

## The field object

`FieldApi<T>` holds the field's current state, its commands, and the pieces
that bind an element. A new object arrives with each change.

| Member | What it is |
| --- | --- |
| `value` | The value the store holds. |
| `name` | The dotted name with array indexes, such as `tasks.0.title`. |
| `errors`, `shownErrors` | Every error, and the ones the `show` setting lets through now. |
| `userErrors` | The errors set with `setErrors`. They come last in `errors`. |
| `touched`, `edited`, `dirty` | Blurred once, changed by the user, different from the baseline. `dirty` needs the `dirty()` plugin. |
| `invalid`, `validating` | Has any error, has a validator running. |
| `disabled`, `readOnly` | Set on this field or one above it. |
| `setValue`, `setTouched`, `setErrors`, `handleBlur`, `reset`, `validate` | The handle's commands. Arrays add `push`, `insert`, `remove` and `move`. |
| `text`, `setText`, `ref` | The pieces for binding an element. See below. |
| `handle` | The field's handle, to pass to another component or keep for later. |
| `id`, `errorId` | Ids for the input and its error list. |

## Props for plain elements

For plain HTML, a props function puts every piece on the element and adds
the rest it needs: `name`, `id`, the value, the change and blur handlers,
`ref`, `disabled`, `readOnly`, and `aria-invalid` and `aria-describedby`
while errors show. There is one function per kind of element, and each
type-checks only on a field of the value type it writes. They are plain
functions, not members, so a form ships only the ones it calls.

| Call | Element | Field type |
| --- | --- | --- |
| `inputProps(field)` or `inputProps(field, { type: "email" })` | `<input>` | string |
| `textareaProps(field)` | `<textarea>` | string |
| `selectProps(field)` | `<select>` | string |
| `numberProps(field)` | `<input type="number">` | number |
| `rangeProps(field)` | `<input type="range">` | number |
| `checkboxProps(field)` | `<input type="checkbox">` | boolean |
| `checkboxGroupProps(field, value)` | one box of a group | array of strings or numbers |
| `radioProps(field, value)` | one radio | string, number or boolean |

`numberProps` and `selectProps` take `empty`, the value an empty input
writes: `numberProps(field, { empty: 0 })`. It defaults to `undefined` and
is required when the field's type has no `undefined`. `numberProps` keeps
`1.` and `-` in the input as typed, the same way `numberPieces` does.

<Only framework="react">

A component given only a handle reads the field object with
`useField(handle)` and passes it on: `inputProps(useField(handle))`. A
custom input records its element with `useFieldRef(handle)`.

</Only>

<Only framework="solid">

Each one also takes `describedBy` as an option, for ids such as a hint's
that go in `aria-describedby` before the error id. It comes last, after the
value for a radio or a box of a group:

```tsx framework=solid
<input {...inputProps(field, { type: "email", describedBy: "email-hint" })} />
<input {...radioProps(field, "pro", { describedBy: "plan-hint" })} />
```

The value, `name`, the flags and the aria props are getters over the field,
so each one updates the element on its own.

A component given only a handle makes the field object with
`createField(handle)` and passes it on: `inputProps(createField(handle))`.
A custom input records its element with `fieldRef(handle)`.

</Only>

## Number inputs

A number field bound with `numberProps(field)`, or by hand with
`numberPieces(field)`, holds a number, or `undefined` while the input is
empty. Some text on the way to a number isn't one yet:

| Typed | Input shows | Field holds |
| --- | --- | --- |
| `12.` | `12.` | `12` |
| `-` | `-` | the value it held before |
| nothing | nothing | `undefined`, or the `empty` option |

The input keeps the typed text while the field still holds the value that
text wrote, so the caret and the `.` don't jump. Once the input loses focus,
or something else writes a different value, it shows the number again.
`numberPieces(field).text` is that text, for an input bound by hand.

## Optional fields

An optional field such as `nickname?: string` starts out `undefined`.
The props functions show `undefined` as an empty input, and a checkbox shows
it unticked. Type the form with `define<T>()` to have optional keys, since
`defaultValues` can't leave a key out and still name it:

```ts
interface Profile {
  name: string;
  nickname?: string;
}

const profile = forms.define<Profile>({ defaultValues: { name: "" } });
```

## Components that take a field

The child of `form.Field` can hand the field to your own component. Type its
prop as `FieldApi<T>`, where `T` is the value type it edits:

```tsx framework=react
import { type FieldApi, inputProps } from "@lunarhue/forms-react";

interface TextInputProps {
  field: FieldApi<string>;
  label: string;
}

function TextInput({ field, label }: TextInputProps) {
  return (
    <label>
      {label}
      <input {...inputProps(field)} />
    </label>
  );
}

<form.Field name="name">{(field) => <TextInput field={field} label="Name" />}</form.Field>;
```

```tsx framework=solid
import { type FieldApi, inputProps } from "@lunarhue/forms-solid";

interface TextInputProps {
  field: FieldApi<string>;
  label: string;
}

function TextInput(props: TextInputProps) {
  return (
    <label>
      {props.label}
      <input {...inputProps(props.field)} />
    </label>
  );
}

<form.Field name="name">{(field) => <TextInput field={field} label="Name" />}</form.Field>;
```

<Only framework="solid">

Read the field through `props.field`. Destructuring it reads each member once
and the component stops updating.

</Only>

To skip the `form.Field` wrapper and get `<form.TextInput name="name" />` on
every form, register the component. See
[Reusable field components](../composition/field-components).

## Binding an element

Component libraries such as Base UI, Radix and React Aria own their labels,
ids and aria, and take a value with a change callback. Give them the pieces
of the field object and leave the rest to them:

| Piece | What it does |
| --- | --- |
| `text` | The text to show: the display text a part such as a mask gives, else the value. |
| `setText(text, from?)` | Writes typed text. With a mask, it also puts the formatted text in the element and places the caret. `from` is the element or an event whose `target` is the element. Without it, the focused element `ref` recorded is used. |
| `handleBlur` | Marks the field touched and runs blur validation. |
| `ref` | Records the element, so an invalid submit can focus it. |

A number input needs a bit more, because `1.` and `-` aren't numbers yet.
`numberPieces(field)` returns its own `text`, `setText` and `handleBlur`.
`setText("-")` writes nothing, `setText("12.")` writes `12`, and `text`
keeps showing what was typed until the value changes or the field blurs.
Empty text writes `undefined`, or the `empty` option:
`numberPieces(field, { empty: 0 })`. The option is required when the field's
type has no `undefined`.

Checkboxes, switches, selects and radio groups hold a value, not text, so
bind `value` and `setValue`.

<Only framework="react">

The demo binds Base UI's `Field`, `Input` and `Checkbox`. Type `1.` in Boxes,
submit it empty, and clear it.

</Only>

<Only framework="solid">

The demo binds plain elements the same way a primitive library takes a
field. Type `1.` in Boxes, submit it empty, and clear it.

</Only>

<Demo name="fields/primitives" />

```tsx framework=react
const { ref } = field;

<Input
  ref={ref}
  value={field.text}
  onValueChange={(text, details) => field.setText(text, details.event)}
  onBlur={field.handleBlur}
/>

<Checkbox.Root ref={ref} checked={field.value} onCheckedChange={(checked) => field.setValue(checked)} />

const number = numberPieces(field);

<Input ref={ref} value={number.text} onValueChange={(text) => number.setText(text)} onBlur={number.handleBlur} />
```

<Only framework="react">

Take `ref` out of the field before passing it, or get it from
`useFieldRef(handle)`. React Compiler treats an object whose member is
passed as `ref` as a ref, so `ref={field.ref}` makes it flag every other
read of `field` during render and skip the component. Inside a
`form.Field` render prop, `ref={field.ref}` is fine, since the Compiler
doesn't check a callback as render code.

</Only>

```tsx framework=solid
<input
  ref={field.ref}
  value={field.text}
  onInput={(event) => field.setText(event.currentTarget.value, event)}
  onBlur={field.handleBlur}
/>

<input
  type="checkbox"
  ref={field.ref}
  checked={field.value}
  onChange={(event) => field.setValue(event.currentTarget.checked)}
/>

const number = numberPieces(field);

<input
  ref={field.ref}
  value={number.text}
  onInput={(event) => number.setText(event.currentTarget.value)}
  onBlur={number.handleBlur}
/>
```

A primitive bound this way shows a reset or a value `persist` restored, since
it reads `text` or `value` on every change. A primitive that keeps its own
text, such as Base UI's `NumberField`, needs `value` and its own change
callback instead of `text`.

<Only framework="react">

A browser can fill inputs back in from before a reload, after the server
markup arrives and before React hydrates. `ref` puts back what React
rendered in a native input, textarea or select, so the input shows what the
form holds. A primitive whose state lives in React, such as a Base UI
checkbox, shows the form's value from its props.

</Only>

<Only framework="solid">

A browser can fill inputs back in from before a reload, after the server
markup arrives and before Solid hydrates. `ref` writes the field's state
into a native input, textarea or select when they differ, so the input shows
what the form holds.

</Only>

## Ids

`field.id` is the form's id followed by the field's path. It stays the same
for the life of the field, including when an array row moves, so it works as
a DOM id and as a list key. The input gets it as `id`, so a
`<label htmlFor={field.id}>` points at the input.

<Only framework="react">

The form's id comes from `useId`, so it matches between the server and the
browser. React 16 and 17 have no `useId`: if you render on the server with
them, pass `id` to `useForm`. See [`id:server`](/errors#react:id:server).

</Only>

`field.errorId` is the id for the element that lists the field's errors.
The props functions point `aria-describedby` at it while errors show, so
screen readers read them with the input. A primitive library that renders
its own error element points at that one instead.
