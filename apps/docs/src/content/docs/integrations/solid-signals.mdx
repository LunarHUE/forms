Want to keep a form synchronized with a Solid 2 signal? `signal()` mirrors values in both directions while letting the form keep its own internal store for validation, touched flags, and error state. Edits in the form update your signal, and external updates to the signal flow back into the form.

## Binding a signal

Pass the getter and setter returned by `createSignal` to `signal()`:

```tsx framework=solid
import { signal } from "@lunarhue/forms-bind/solid";
import { createForm } from "@lunarhue/forms-solid";
import { createSignal } from "solid-js";

const [settings, setSettings] = createSignal({
  displayName: "Ada",
  timezone: "Europe/London",
});

const form = createForm(settingsForm, {
  plugins: [signal(settings, setSettings)],
});
```

If your signal lives at module scope, you can put `signal(...)` in `forms.define({ plugins: [...] })` instead. Passed to `createForm`, it runs after shared and definition plugins.

TypeScript verifies that the getter, setter, and form all share the same value type.

## Reactivity and timing

Form edits update the signal synchronously. In the other direction, external signal writes propagate into the form when Solid flushes its effects (not on the exact same line as `setSettings(...)`).

Under the hood, the binding tracks the signal inside its own reactive root, created when the form gets its first listener (on mount) and disposed when the last listener unmounts—catching up automatically if it remounts later. It also calls the setter outside any reactive owner so writes triggered during rendering or memos won't throw.

Each form supports one external binding.

## Options

| Option | Default | What it does |
| --- | --- | --- |
| `initial` | `"outside"` | Chooses the initial source of truth. `"outside"` starts the form from the signal's value (including during SSR). `"form"` keeps `defaultValues` and writes them to the signal once mounted. |
| `incoming` | `"replace"` | Controls how external signal changes apply. `"replace"` overwrites the form values. `"rebase"` moves the baseline forward while keeping fields the user edited. You can also pass a custom per-field resolver, just like [rebase](../plugins/rebase). |

```tsx
signal(settings, setSettings, { initial: "form", incoming: "rebase" });
```

For anything other than a plain signal (such as a Solid store), use `bind()` from `@lunarhue/forms-solid/plugins` with `get`, `set`, and `subscribe` callbacks and the same options.
