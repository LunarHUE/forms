If part of your app already lives in Zustand 5 and you want a form to stay in sync with it, `zustand()` bridges the two. Your form keeps its own internal store for errors, touched state, and validation; the plugin simply copies values both ways. Edits in the form update Zustand, and updates to Zustand flow back into the form.

## Binding a whole store

If your Zustand store holds *only* the form's state (no action functions mixed in), pass the store directly:

```tsx
import { zustand } from "@lunarhue/forms-bind/zustand";
import { create } from "zustand";

const useProfileStore = create(() => ({ name: "", email: "" }));

const profile = forms.define({
  defaultValues: { name: "", email: "" },
  plugins: [zustand(useProfileStore)],
  onSubmit: saveProfile,
});
```

Because form writes call `setState` with the whole form value, use the slice form below whenever your store also holds actions or unrelated state.

## Binding a slice of a larger store

Pass `select` to pick the slice that belongs to the form, and `update` to map the form's value back into a partial state update:

```tsx
zustand(useAppStore, {
  select: (state) => state.settings,
  update: (settings) => ({ settings }),
});
```

Unrelated changes elsewhere in `useAppStore` won't touch the form as long as `select` returns the same reference.

`update` also receives the store's current `state` as its second argument, which helps when your slice lives inside a record or map and you want to keep sibling keys intact:

```tsx
zustand(useReviewStore, {
  select: (state) => state.summaries[reviewKey],
  update: (summary, state) => ({ summaries: { ...state.summaries, [reviewKey]: summary } }),
});
```

If your `select` builds a fresh object on every call (like picking two top-level keys), pass `isEqual` so updates to unrelated fields don't look like a new slice:

```tsx
zustand(useReviewStore, {
  select: ({ verdict, body }) => ({ verdict, body }),
  update: (review) => review,
  isEqual: (previous, next) => previous.verdict === next.verdict && previous.body === next.body,
});
```

(`isEqual` defaults to `Object.is`.)

## Where to install the binding

If the Zustand store lives at module scope, put `zustand(...)` in `forms.define({ plugins: [...] })`. If the store is created inside a component or passed via props, attach it in `useForm` instead (instance plugins run after shared and definition plugins):

```tsx framework=react
const form = useForm(settingsForm, {
  plugins: [zustand(store, { select, update })],
});
```

TypeScript checks that the bound slice matches your form's value type, so mismatches fail at compile time.

Each form can have one external binding. The binding only subscribes to Zustand while the form has active listeners (while mounted), and catches up if the store changed while unmounted.

## Options

Both forms of `zustand()` accept two options to control sync direction and conflicts:

| Option | Default | What it does |
| --- | --- | --- |
| `initial` | `"outside"` | Sets the source of truth on startup. `"outside"` initializes the form from Zustand (including during SSR). `"form"` keeps `defaultValues` and pushes them to Zustand when the form mounts. |
| `incoming` | `"replace"` | Decides how external Zustand updates apply to the form. `"replace"` overwrites the form values. `"rebase"` advances the baseline while preserving fields the user edited. You can also pass a custom resolver function, just like [rebase](../plugins/rebase). |

```tsx
zustand(useProfileStore, { incoming: "rebase" });
```

Using `incoming: "rebase"` works well when a background fetch updates Zustand: untouched fields pick up the fresh data while anything the user is editing stays safe.

Need to sync with a store other than Zustand? Use the generic `bind()` plugin from `@lunarhue/forms-react/plugins`, which takes `{ get, set, subscribe }` along with the same `initial` and `incoming` options.
