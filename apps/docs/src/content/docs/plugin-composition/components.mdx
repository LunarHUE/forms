UI elements like a "changed" badge on inputs, an undo button, or a sticky save bar usually belong across *every* form in your app, not duplicated in each form component. Below, a single shared save bar works under any form from the same `createForms`, and `TextField` automatically highlights itself when edited.

## Declaring plugin requirements on a field component

If a field component reads plugin state (like `field.dirty`), declare the plugins it requires in the second type argument of `FieldApi`, using `typeof` on their factory functions (e.g., `typeof dirty | typeof history`). The third type argument is the error type, which defaults to `FormError`.

```tsx framework=react
interface TextFieldProps {
  field: FieldApi<string, typeof dirty>;
  label: string;
}

function TextField({ field, label }: TextFieldProps) {
  return (
    <label>
      {field.dirty ? `${label} (changed)` : label}
      <input {...inputProps(field)} />
    </label>
  );
}
```

```tsx framework=solid
interface TextFieldProps {
  field: FieldApi<string, typeof dirty>;
  label: string;
}

function TextField(props: TextFieldProps) {
  return (
    <label>
      {props.field.dirty ? `${props.label} (changed)` : props.label}
      <input {...inputProps(props.field)} />
    </label>
  );
}
```

Import `dirty` as a type (`import type { dirty } from "@lunarhue/forms-react/plugins"`). Without that second type argument, reading `field.dirty` is a compile error—and with it, TypeScript ensures `TextField` can only be used on forms that actually install `dirty()`.

## Reading shared plugins from context

A shared save bar can't hardcode a single form definition—it needs to work with *whichever* form it's rendered inside. Pass your `forms` object (from `createForms`) to `useFormContext(forms)` to grab the nearest matching form above it:

```tsx framework=react
export const forms = createForms({ plugins: [dirty(), history()], fields: { TextField } });

function SaveBar() {
  const form = useFormContext(forms);
  const changed = useFormState(form, (state) => state.dirty);
  const canUndo = useFormState(form, (state) => history.formMeta(state).canUndo);
  return (
    <div>
      <button type="button" disabled={!canUndo} onClick={() => form.plugins.history.undo()}>
        Undo
      </button>
      <button type="submit" disabled={!changed}>
        Save
      </button>
    </div>
  );
}
```

```tsx framework=solid
export const forms = createForms({ plugins: [dirty(), history()], fields: { TextField } });

function SaveBar() {
  const form = useFormContext(forms);
  return (
    <div>
      <button
        type="button"
        disabled={!history.formMeta(form.state).canUndo}
        onClick={() => form.plugins.history.undo()}
      >
        Undo
      </button>
      <button type="submit" disabled={!form.state.dirty}>
        Save
      </button>
    </div>
  );
}
```

Because `forms` knows about your shared plugins, error type, and registered components, `form.plugins.history`, `state.dirty`, and `form.TextField` all type-check automatically—even though the specific form's value type is unknown. (Plugins added only to an individual form definition aren't included on the shared context type.)

Remember to wrap the `<form>` in `<form.Form>` so the context is provided—see [Reading the form from context](../basics/submit#reading-the-form-from-context). Calling `useFormContext(forms)` without a matching `<form.Form>` above it throws an error.

## Passing the form as a prop instead

If you'd rather pass the form explicitly as a prop instead of using context, type the prop as `FormOf<typeof forms>`:

```tsx framework=react
interface SaveBarProps {
  form: FormOf<typeof forms>;
}

function SaveBar({ form }: SaveBarProps) {
  // ...
}
```

```tsx framework=solid
interface SaveBarProps {
  form: FormOf<typeof forms>;
}

function SaveBar(props: SaveBarProps) {
  // ...
}
```

Any form created from `forms` will match that prop type cleanly.
