An undo button or a save bar belongs on every form, not in each definition.
The bar below works under any form from the same `createForms`, and the text
field marks itself changed.

## A field component that reads a plugin

A component that reads a plugin's member from its field says so in its type.
The second type argument of `FieldApi` names the plugins it needs, by their
factories, as `typeof dirty | typeof history`. The third is the error type,
`FormError` by default:

```tsx framework=react
interface TextFieldProps {
  field: FieldApi<string, typeof dirty>;
  label: string;
}

function TextField({ field, label }: TextFieldProps) {
  return (
    <label>
      {field.dirty ? `${label} (changed)` : label}
      <input {...inputProps(field)} />
    </label>
  );
}
```

```tsx framework=solid
interface TextFieldProps {
  field: FieldApi<string, typeof dirty>;
  label: string;
}

function TextField(props: TextFieldProps) {
  return (
    <label>
      {props.field.dirty ? `${props.label} (changed)` : props.label}
      <input {...inputProps(props.field)} />
    </label>
  );
}
```

Import `dirty` as a type, from your adapter's `plugins` entry. The component
then fits only forms with `dirty()`. Without the second argument,
`field.dirty` is a type error.

## The form from context

A component shared by many forms can't name one definition. Pass the object
`createForms` returned to `useFormContext` instead. It returns the nearest
form above that one of its definitions made, and skips forms from other
`createForms` calls:

```tsx framework=react
export const forms = createForms({ plugins: [dirty(), history()], fields: { TextField } });

function SaveBar() {
  const form = useFormContext(forms);
  const changed = useFormState(form, (state) => state.dirty);
  const canUndo = useFormState(form, (state) => history.formMeta(state).canUndo);
  return (
    <div>
      <button type="button" disabled={!canUndo} onClick={() => form.plugins.history.undo()}>
        Undo
      </button>
      <button type="submit" disabled={!changed}>
        Save
      </button>
    </div>
  );
}
```

```tsx framework=solid
export const forms = createForms({ plugins: [dirty(), history()], fields: { TextField } });

function SaveBar() {
  const form = useFormContext(forms);
  return (
    <div>
      <button
        type="button"
        disabled={!history.formMeta(form.state).canUndo}
        onClick={() => form.plugins.history.undo()}
      >
        Undo
      </button>
      <button type="submit" disabled={!form.state.dirty}>
        Save
      </button>
    </div>
  );
}
```

The form's type knows the shared plugins, the error type and the registered
field components, so `form.plugins.history`, `dirty` and `form.TextField` all
type-check. Its value type is unknown, and plugins added by a definition or
by one form are not in its type. A form is above when the component renders
inside its `form.Form`, as [Submit](../basics/submit#a-submit-button-from-context)
shows. `useFormContext` throws when no form of
those forms is above.

## Passing the form as a prop

To take the form as a prop instead, type it `FormOf<typeof forms>`:

```tsx framework=react
interface SaveBarProps {
  form: FormOf<typeof forms>;
}

function SaveBar({ form }: SaveBarProps) {
  // ...
}
```

```tsx framework=solid
interface SaveBarProps {
  form: FormOf<typeof forms>;
}

function SaveBar(props: SaveBarProps) {
  // ...
}
```

Any form from `forms` fits.
