A **part** is a small bundle of hooks attached to a single field, either standalone (like a text mask) or tied to a plugin. When you attach a part to a field type with `defineField`, every form that renders that field gets the behavior automatically. That way, phone formatting lives with `PhoneField` instead of being repeated in every form definition.

All three inputs in the demo below are built from the same `TextInput` component.

## Attaching parts to field types

Pass your component followed by any number of parts to `defineField`, then register the resulting field types on `createForms`. Keeping them in a shared `fields.ts` module makes them easy to reuse across your app (`masked`, `digits`, and `upper` come from your adapter's `text` entry).

```ts title="fields.ts"
export const PhoneField = defineField(
  TextInput,
  masked({ clean: (value, input) => digits(value, input).slice(0, 10), display: formatPhone }),
);
export const CodeField = defineField(TextInput, masked({ clean: upper, display: (value) => value }));
```

```ts title="contact.tsx"
const forms = createForms({ fields: { TextInput, PhoneField, CodeField } });
```

Now `<form.PhoneField name="phone" />` stores digits while displaying a formatted phone number, and `<form.TextInput name="name" />` renders the same component with no mask. Because masks are standalone parts, your form doesn't need to install any plugin for them.

TypeScript checks parts in two places so misconfigurations fail early:

- **Wrong value type:** `masked` only works on string fields, so `defineField(NumberInput, masked(...))` is a compile error.
- **Missing plugin:** if a part requires a plugin that isn't installed on the form, TypeScript tells you directly (for example, `Add limit() to this form's plugins: ShortNote uses it`). See [Parts](../writing-plugins/parts) for how plugin-backed parts work.

## When parts attach (and pinning with `at()`)

By default, a field type's parts attach the first time that field renders. For most fields that's enough, since the user can't type into an unrendered input anyway.

If a field's part needs to be active *before* it ever renders (say, on a later wizard step or during SSR), pin it onto the form definition with `.at()`:

```ts
const contact = forms.define({ defaultValues, onSubmit }, PhoneField.at("phone"));
```

Pinned parts attach as soon as the store is created, so they are already active in server-rendered HTML. Rendering `<form.PhoneField name="phone" />` later won't attach the part a second time.
