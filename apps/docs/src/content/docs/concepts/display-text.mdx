The form holds values: `field.value`, what `onSubmit` gets, what validators
check. An input shows text. For most string fields the two are the same. They
differ in two places: number inputs, and fields a plugin formats, such as a
phone number. Type in the demo and compare the input with the line under it.

## Number inputs

A number field bound with `inputProps(field, { kind: "number" })`, or with
`field.setNumberText`, holds a number, or `undefined` while the input is
empty. Some text on the way to a number isn't one yet:

| Typed | Input shows | Field holds |
| --- | --- | --- |
| `12.` | `12.` | `12` |
| `-` | `-` | the value it held before |
| nothing | nothing | `undefined`, or the `empty` option |

`field.text` keeps the typed text while the field still holds the value that
text wrote, so the caret and the `.` don't jump. Once the input loses focus,
or something else writes a different value, it shows the number again.

## Formatted fields

A plugin can give a field display text: a function from the stored value to
the text the input shows. A `masked` part does this with `display`:

```ts
const PhoneField = defineField(PhoneInput, masked({ clean: digits, display: formatPhone }));
```

The store holds `5551234567` and the input shows `(555) 123-4567`. Each
keystroke goes through `clean` on its way into the store, and the input
shows `display` of the result, with the caret kept where the user is typing.
[Masks](../plugins/masks) covers the options.

Text inputs and textareas show display text, on the server too, so the page
hydrates with it. Number, checkbox, radio and select inputs ignore it.

Keep `display` a pure function of the value. The server and the browser both
call it, and it runs on every change.

## What reads which

Everything except the input reads the stored value: `field.value`, the
schema, `onSubmit`, `dirty`, history and persistence. The display text lives
only in `field.text`, which `inputProps(field)` uses too. An input bound to
`field.value` instead shows the stored value. To keep the caret in place,
write with `field.setText(text, event)`. See
[Binding an element](./fields#binding-an-element).

To give a field display text from your own plugin, return a `display` hook
from its `attach`. See [Writing a plugin](../plugins/writing-a-plugin).
