A field component is your own component with a `field` prop. Register it on
`createForms` and every form gets it as a member, `form.TextField`, that
takes a field name instead of the `field` prop.

<Demo name="fields/profile" />

## Registering a component

Type the prop as `FieldApi<T>`, where `T` is the value type the component
edits. List the component under `fields`:

```tsx framework=react
import { createForms, type FieldApi, inputProps } from "@lunarhue/forms-react";

function TextField({ field, label }: { field: FieldApi<string>; label: string }) {
  return (
    <label>
      {label}
      <input {...inputProps(field)} />
    </label>
  );
}

const forms = createForms({ fields: { TextField } });
```

```tsx framework=solid
import { createForms, type FieldApi, inputProps } from "@lunarhue/forms-solid";

function TextField(props: { field: FieldApi<string>; label: string }) {
  return (
    <label>
      {props.label}
      <input {...inputProps(props.field)} />
    </label>
  );
}

const forms = createForms({ fields: { TextField } });
```

<Only framework="solid">

Read the field through `props.field`. Destructuring it reads each member
once and the component stops updating.

</Only>

`form.TextField` takes the component's own props, minus `field`, plus one of:

- `name`, a field name such as `"address.city"`. The compiler checks it, and
  only names whose value fits the component are accepted: a `FieldApi<string>`
  component won't take a number field. See [Typed paths](./typed-paths).
- `handle`, a field handle from `form.root.at(...)` or an array row.

For a one-off input, `form.Field` passes the same object to a function
child, with no registration:

```tsx framework=react
<form.Field name="name">{(field) => <input {...inputProps(field)} />}</form.Field>
```

```tsx framework=solid
<form.Field name="name">{(field) => <input {...inputProps(field)} />}</form.Field>
```

## The field object

`FieldApi<T>` holds the field's current state, its commands, and the pieces
that bind an element. A new object arrives with each change.

| Member | What it is |
| --- | --- |
| `value` | The value the store holds. |
| `name` | The dotted name with array indexes, such as `tasks.0.title`. |
| `errors`, `shownErrors` | Every error, and the ones the `show` setting lets through now. |
| `userErrors` | The errors set with `setErrors`. They come last in `errors`. |
| `touched`, `edited`, `dirty` | Blurred once, changed by the user, different from the baseline. `dirty` needs the `dirty()` plugin. |
| `invalid`, `validating` | Has any error, has a validator running. |
| `disabled`, `readOnly` | Set on this field or one above it. |
| `setValue`, `setTouched`, `setErrors`, `handleBlur`, `reset`, `validate` | The handle's commands. Arrays add `push`, `insert`, `remove` and `move`. |
| `text`, `setText`, `setNumberText`, `ref` | The pieces for binding an element. See below. |
| `handle` | The field's handle, to pass to another component or keep for later. |
| `id`, `errorId` | Ids for the input and its error list. |

`FieldApi<number>` has `value: number | undefined`, since a schema form starts
a number field empty. `FieldApi<string>` is a plain string.

## Optional fields

A `FieldApi<string>` component takes required string fields only. An optional
field such as `nick?: string` starts out `undefined`, and a component that
reads `field.value` as a `string` would get it wrong. To render optional
fields too, put `undefined` in the type:

```tsx framework=react
function TextField({ field, label }: { field: FieldApi<string | undefined>; label: string }) {
  return (
    <label>
      {label}
      <input {...inputProps(field)} />
    </label>
  );
}
```

```tsx framework=solid
function TextField(props: { field: FieldApi<string | undefined>; label: string }) {
  return (
    <label>
      {props.label}
      <input {...inputProps(props.field)} />
    </label>
  );
}
```

This component takes `name: string` and `nick?: string` alike, whether the
form's type comes from `define<T>()` or from a schema. `inputProps` shows
`undefined` as an empty input. A checkbox does the same with
`FieldApi<boolean | undefined>`, and shows `undefined` unticked. `null` works
the same way: `FieldApi<string | null>` takes `string` and `string | null`
fields.

The type checker doesn't stop such a component from writing `undefined` into
a required field, so leave writes to `inputProps` or write a value of the
field's own type. A `FieldApi<number>` component has the same gap.

In a component generic over its value, such as `<T extends Profile>`, pass an
optional child by `name`. Its handle from `field.at("nick")` doesn't fit.

## Binding an element

Component libraries such as Base UI, Radix and React Aria own their labels,
ids and aria, and take a value with a change callback. Give them the pieces
of the field object and leave the rest to them:

| Piece | What it does |
| --- | --- |
| `text` | The text to show: number text the user is typing, else the display text a plugin such as a mask gives, else the value. |
| `setText(text, from?)` | Writes typed text. With a mask, it also puts the formatted text in the element and places the caret. `from` is the element or an event whose `target` is the element. Without it, the focused element `ref` recorded is used. |
| `setNumberText(text, empty?)` | Writes text typed in a number field. `-` writes nothing yet, `12.` writes `12`, and empty text writes `empty`. |
| `handleBlur` | Marks the field touched, runs blur validation, and drops typed number text. |
| `ref` | Records the element, so an invalid submit can focus it. |

Checkboxes, switches, selects and radio groups hold a value, not text, so
bind `value` and `setValue`.

<Only framework="react">

The demo binds Base UI's `Field`, `Input` and `Checkbox`. Type in the middle
of the phone number, type `1.` in Boxes, submit it empty, and clear it.

</Only>

<Only framework="solid">

The demo binds plain elements the same way a primitive library takes a
field. Type in the middle of the phone number, type `1.` in Boxes, submit it
empty, and clear it.

</Only>

<Demo name="fields/primitives" />

```tsx framework=react
const { ref } = field;

<Input
  ref={ref}
  value={field.text}
  onValueChange={(text, details) => field.setText(text, details.event)}
  onBlur={field.handleBlur}
/>

<Checkbox.Root ref={ref} checked={field.value} onCheckedChange={(checked) => field.setValue(checked)} />
```

<Only framework="react">

Take `ref` out of the field before passing it. React Compiler's lint treats
an object whose member is passed as `ref` as a ref, and flags every other
read of `field` during render.

</Only>

```tsx framework=solid
<input
  ref={field.ref}
  value={field.text}
  onInput={(event) => field.setText(event.currentTarget.value, event)}
  onBlur={field.handleBlur}
/>

<input type="checkbox" ref={field.ref} checked={field.value} onChange={(event) => field.setValue(event.currentTarget.checked)} />
```

A primitive bound this way shows a reset or a value `persist` restored, since
it reads `text` or `value` on every change. A primitive that keeps its own
text, such as Base UI's `NumberField`, needs `value` and its own change
callback instead of `text`.

<Only framework="react">

A browser can fill inputs back in from before a reload, after the server
markup arrives and before React hydrates. `ref` puts back what React
rendered in a native input, textarea or select, so the input shows what the
form holds. A primitive whose state lives in React, such as a Base UI
checkbox, shows the form's value from its props.

</Only>

<Only framework="solid">

A browser can fill inputs back in from before a reload, after the server
markup arrives and before Solid hydrates. `ref` writes the field's state
into a native input, textarea or select when they differ, so the input shows
what the form holds.

</Only>

## inputProps

For plain HTML, `inputProps(field)` puts every piece on the element and
adds the rest an `<input>` needs: `name`, `id`, `value`, the change and blur
handlers, `ref`, `disabled`, `readOnly`, and `aria-invalid` and
`aria-describedby` while errors show. It is a function, not a member, so a
form that never calls it doesn't ship it. Pass options for other kinds of
input. The compiler checks them against the field's value type.

| Call | Element | Field type |
| --- | --- | --- |
| `inputProps(field)` or `inputProps(field, { type: "email" })` | `<input>` | string |
| `inputProps(field, { kind: "textarea" })` | `<textarea>` | string |
| `inputProps(field, { kind: "select" })` | `<select>` | string |
| `inputProps(field, { kind: "number" })` or `{ kind: "range" }` | `<input type="number">` or `"range"` | number |
| `inputProps(field, { kind: "checkbox" })` | `<input type="checkbox">` | boolean |
| `inputProps(field, { kind: "checkbox", value })` | one box of a group | array of strings or numbers |
| `inputProps(field, { kind: "radio", value })` | one radio | string, number or boolean |

Number and select inputs take `empty`, the value an empty input writes. It
defaults to `undefined` and is required when the field's type has no
`undefined`.

<Only framework="react">

A component given only a handle records its element with
`useFieldRef(handle)` and gets the props from `useInputProps(handle)`.

</Only>

<Only framework="solid">

A component given only a handle records its element with `fieldRef(handle)`
and gets the props from `createInputProps(handle)`.

</Only>

## Ids

`field.id` is the form's id followed by the field's path. It stays the same
for the life of the field, including when an array row moves, so it works as
a DOM id and as a list key. The input gets it as `id`, so a
`<label htmlFor={field.id}>` points at the input.

<Only framework="react">

The form's id comes from `useId`, so it matches between the server and the
browser. React 16 and 17 have no `useId`: if you render on the server with
them, pass `id` to `useForm`. See [`id:server`](/errors#react:id:server).

</Only>

`field.errorId` is the id for the element that lists the field's errors.
`inputProps(field)` points `aria-describedby` at it while errors show, so
screen readers read them with the input. A primitive library that renders
its own error element points at that one instead.

## Shown errors

`errors` has every error on the field. `shownErrors` has the ones the user
should see now, and `aria-invalid` follows it. Render `shownErrors`.

The `show` setting decides. Set it on `createForms` for every form or on
`define` for one:

| `show` | Errors show |
| --- | --- |
| `"touched-or-submitted"` | after the field is blurred or the form submitted (the default) |
| `"touched"` | after the field is blurred |
| `"submitted"` | after the first submit |
| `"always"` | at once |

A function works too. It gets `touched`, `edited`, `dirty` and `submitCount`
and returns true to show.
