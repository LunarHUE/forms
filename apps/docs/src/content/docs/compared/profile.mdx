A settings form that loads its values from the server, built once with
`@lunarhue/forms` and once with [TanStack Form](https://tanstack.com/form).
Both builds render the same markup and call the same fake server. Switch the
build on the preview: they behave the same.

<Compare app="profile" />

## What the form does

Name, email, bio, time zone and a nested `notifications` object, checked by
one Zod schema and loaded from the server first.

Each changed field gets a mark, and typing the original value back clears it.
The save bar counts the changes, and Save stays disabled while there are none.
After a save the form is clean again, except for fields edited while the save
ran. Discard goes back to the last saved copy.

"Edit on the server" changes the profile behind the form's back. Refresh then
takes the server's copy for every field you haven't changed and keeps the ones
you have.

## Where the code differs

Our side has `zod()`, `dirty()` and `rebase()` in its plugins and
`baselineOnSubmit()` on the form. The save bar reads the change count from
`store.changes()`, and Refresh is one `rebase` call that says which fields take
the server's value.

`store.changes()` is a read, not a subscription, and the form's state doesn't
change on a second edit while the form is already dirty. So the save bar reads
the count under `useField(form.root, ...)`, which runs again on every value
change. That is a detail a reader of our side has to know.

TanStack's side uses its Standard Schema support for Zod, `isDefaultValue`,
`form.reset`, `formOptions` and `withForm`. Its choices:

- `isDirty` stays true once the user types, even when they type the original
  back. The marks and the count read `isDefaultValue` instead.
- TanStack has no call that moves the defaults and keeps some values. A small
  helper, `rebaseline`, reads the fields to keep, calls `form.reset(values)`,
  and writes the kept ones back. The save and Refresh both use it, walking a
  hand-kept list of the form's fields.
- `useForm` applies its options again on every render, and an untouched form
  takes new `defaultValues` as its values. Defaults moved with
  `form.reset(values)` would snap back on the next render, so the form keeps
  its defaults in React state and moves them after every save and refresh.
  Refresh lives in the form component for that reason, and the save bar gets
  it as a prop.
- `withForm` types the save bar from `formOptions`, which want default values,
  but the real ones are loaded. The shared options carry a blank profile, and
  `useAppForm` gets the loaded one.
- TanStack's field context can't tie a select's options to the field's value
  type, so `Select` takes strings.

## How it was measured

[`scripts/size-compare.ts`](https://github.com/LunarHUE/forms/blob/main/scripts/size-compare.ts)
builds each app with Vite for production, minified, three times per library.
Only JavaScript counts. **Forms + app** leaves out React, react-dom and Zod,
**Total** is everything the page loads, and **App only** leaves out the form
libraries too. Zod is in **Total** on both sides, since both validate with the
same schema.

Our packages are measured from their built files, as an app that installs them
would get them. TanStack Form is 1.33.5, the latest stable release. CI fails
when the numbers in the repo are stale. The apps and their specs are in
[`examples/compare`](https://github.com/LunarHUE/forms/tree/main/examples/compare).
