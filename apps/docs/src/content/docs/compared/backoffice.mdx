A back-office workspace with three record forms and an invite dialog, built once with `@lunarhue/forms` and once with [TanStack Form](https://tanstack.com/form). Schemas, formatters, and markup are shared across both builds so you are comparing form wiring only. Switch builds in the preview below; both behave the same.

## What the workspace does

Each record form loads from the mock server and shares a save bar (with change count, Undo, Discard, and Save) plus an error summary after a failed submit:

- **Customer:** contact details, billing address, and a conditional shipping address shown only when "Ship to the billing address" is unchecked (whose errors only count while visible).
- **Order:** dynamic line items (SKU, quantity, price) with a live running total, plus a conditional gift message.
- **Company settings:** name, phone, tax ID, and registered address. Submitting tax ID `00-0000000` triggers a server refusal that stays on the field until edited.
- **Invite a teammate:** a modal dialog whose draft persists across closing the dialog and reloading the page.

Across every address, the State field only appears for US addresses. Phone, tax ID, quantity, and price fields are masked, storing clean digits (or decimals) while displaying formatted text.

## Where the two implementations differ

On the `@lunarhue/forms` side, one `createForms` installs `zod()`, `dirty()`, `rebase()`, `rules()`, `arrays()`, and `history()`. Masks attach via `masked(...)` parts on `PhoneField` and `MoneyField` (no plugin needed), the US-state rule travels inside `AddressFieldset`, the save bar and error summary find their form via `useFormContext(forms)` inside `<form.Form>`, and the invite dialog persists with a single `persist("backoffice-invite")` plugin.

On the TanStack Form side, `createFormHook` provides the shared form components, `withFieldGroup` handles addresses, and Standard Schema + `isDefaultValue` + `form.reset` cover validation and dirty state. The rest is implemented in app code:

- **Masks:** a custom `MaskedInput` cleans values and restores the caret by clean-character count (a real app would usually reach for a dedicated masking library; this minimal one doesn't step over separators on backspace).
- **Undo:** since TanStack doesn't ship history, field components and line-item buttons record previous values manually and replay them with `setFieldValue`.
- **Conditional rules:** each conditional field wraps itself in `form.Subscribe` or `useStore` inside every form.
- **Change counts and Refresh:** reuses the `rebaseline` pattern from the [profile comparison](./profile), walking leaf paths like `lines[0].price`.
- **Invite draft:** reads `localStorage` once for initial defaults and writes back inside an effect on every change.

A few extra details were needed on the TanStack side to keep behavior identical:
- Defaults are mirrored in React state after every save, refresh, and invite so `useForm` doesn't snap them back on re-render.
- Because the form context's `options` don't reflect `reset(values)`, the save bar takes current defaults as a prop and undo stacks are keyed by `formId`.
- Input IDs are constructed from `formId` + field name so error summary links can jump to inputs.
- Order totals subscribe to `lines` directly (since array fields only re-render on row add/remove), and rows are keyed by index per TanStack's docs.
- Record forms save inside `onSubmit` and attach server refusals via `form.setErrorMap`; because `isSubmitSuccessful` stays set, the "Saved" message lives in React state.

## Why our single bundle looks heavier here

This comparison is one flat app with no router. All four screens (Customer, Order, Company settings and the invite dialog) are imported eagerly into a single bundle, and one `createForms` in `forms.ts` installs `zod()`, `dirty()`, `rebase()`, `rules()`, `arrays()` and `history()` for every form. The invite dialog adds `persist()`, and the masked field types bring the `masked()` part. We kept it that way so the numbers compare form code and nothing else. A real multi-screen app shouldn't ship like this.

Most of these plugins only matter on one or two screens. `arrays()` is for the Order line items. `dirty()`, `rebase()` and `history()` drive the save bar's change count, Refresh and Undo, which the invite dialog never shows. Put everything on one global `createForms` and every screen pays for all of it on first load.

In a real app, two changes get most of that back:

- **Split by route.** Lazy-load each record screen when the user navigates to it, and load dialogs or wizard steps when they open. The invite dialog's code shouldn't load until someone clicks Invite.
- **Attach plugins where they're used.** Keep the shared `createForms` to what every form needs (`zod()`, and `rules()` if every screen has conditional fields), and pass the rest through each form's `define({ plugins })`, the way `inviteForm` already does with `persist()`. Then `arrays()` ships with the Order route and `history()` with the screens that have Undo.

With both, each route's chunk carries only the plugins its forms use. This flat bundle hides that advantage, because nothing here is ever left out. A small form with no plugins at all, like a search box or a dialog without a saved draft, can go further and use [`/mini`](../basics/mini). The invite dialog here can't, since `/mini` has no plugin host and the draft needs `persist()`.

## How bundle sizes were measured

[`scripts/size-compare.ts`](https://github.com/LunarHUE/forms/blob/main/scripts/size-compare.ts) builds each app for production (minified, JS only) in three slices: **App only** (excluding React, `react-dom`, Zod, and the form libraries, so TanStack's hand-written masks, undo, and draft persistence count here while our plugins don't), **Forms + app** (adding the form library, so our plugins count here), and **Total** (everything).

Measured from built package outputs against TanStack Form 1.33.5 and enforced in CI. Source and shared Playwright specs are in [`examples/compare`](https://github.com/LunarHUE/forms/tree/main/examples/compare).
