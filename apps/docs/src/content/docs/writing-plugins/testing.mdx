Once your plugin works in your app, you can test it against `@lunarhue/forms-core` (no DOM or framework needed) and publish it so both React and Solid users can install it.

## How official third-party packages are structured

Official plugins that depend on external libraries live in their own packages with one subpath entry per library and optional peer dependencies, so apps only install what they use (framework adapters don't re-export them):

- **`@lunarhue/forms-schema`** provides schema default adapters (`@lunarhue/forms-schema/zod`, `@lunarhue/forms-schema/valibot`). See [Schema adapters](./schema-adapters) to build one for another library.
- **`@lunarhue/forms-bind`** provides two-way state bindings built on top of `bind()`.

<Only framework="react">

```ts
import { zustand } from "@lunarhue/forms-bind/zustand";

// Bind the whole store state (only when the store holds no actions):
const form = useForm(profile, { plugins: [zustand(useProfileStore)] });

// Or bind a single slice:
zustand(useAppStore, { select: (state) => state.profile, update: (profile) => ({ profile }) });
```

See [Zustand](../integrations/zustand) for the complete walkthrough.

</Only>

<Only framework="solid">

```ts
import { signal } from "@lunarhue/forms-bind/solid";

const [settings, setSettings] = createSignal({ displayName: "Ada", timezone: "Europe/London" });
const form = createForm(settingsForm, { plugins: [signal(settings, setSettings)] });
```

See [Solid signals](../integrations/solid-signals) for the complete walkthrough.

</Only>

Both packages declare `@lunarhue/forms-core` as a peer dependency so the app shares a single copy of core. If two copies end up installed, development builds log a warning.

## Publishing a community plugin

Follow three conventions when publishing your own plugin:
1. Name the package `forms-plugin-<name>`.
2. Build it against `@lunarhue/forms-core/plugins` and never import `@lunarhue/forms-react` or `@lunarhue/forms-solid`. Because every adapter wraps the same core store, a core plugin works across React, Solid, and future adapters.
3. Put `@lunarhue/forms-core` in `peerDependencies` (and `devDependencies` for your own test suite):

```json
{
  "name": "forms-plugin-trim",
  "peerDependencies": { "@lunarhue/forms-core": "^0.2.0" },
  "devDependencies": { "@lunarhue/forms-core": "^0.2.0" }
}
```

## Testing a plugin with `testStore`

`@lunarhue/forms-core/plugins/testing` ships a `testStore` helper for plugin tests. It has no test-runner dependencies, so it works in Vitest, Jest, `node:test`, or `bun:test`, and lives on its own entry point so it never ends up in app bundles.

```ts
import { definePlugin } from "@lunarhue/forms-core/plugins";
import { testStore } from "@lunarhue/forms-core/plugins/testing";
import { expect, it } from "vitest";

// Trims leading/trailing whitespace on the listed fields.
const trim = definePlugin({
  name: "trim",
  setup: (_ctx, fields: readonly string[]) => ({
    beforeWrite: (write) =>
      typeof write.value === "string" && fields.includes(write.path.join(".")) ? write.value.trim() : write.value,
  }),
});

it("trims the fields it names", () => {
  const { store, records, errors } = testStore({ defaultValues: { name: "", note: "" }, plugins: [trim(["name"])] });
  store.root.at("name").setValue("  Ada ");
  store.root.at("note").setValue(" hi ");
  expect(store.root.peek().value).toEqual({ name: "Ada", note: " hi " });
  expect(records.sync[0]).toMatchObject({ path: ["name"], after: "Ada", cause: "user" });
  expect(errors).toEqual([]);
});
```

`testStore` accepts the same config and trailing parts as `define` (`defaultValues`, `schema`, `validate`, `onSubmit`, `plugins`, and so on) and returns:

- **`store`**: a fully typed form store (`store.plugins.<name>` works just like in an app). Drive it directly with `setValue`, `submit()` (runs `beforeSubmit` and `onSubmitted`), `reset()` (runs `onReset`), and `handleBlur()` (runs `onBlur`).
- **`records`**: captures write records delivered at each timing: `records.sync`, `records.deferred`, and `records.idle` (clear between steps with `records.sync.length = 0`).
- **`errors`**: collects any `{ plugin, error }` thrown by plugin hooks instead of rethrowing, so end each test with `expect(errors).toEqual([])`.
- **`flush()`**: synchronously flushes waiting `deferred` and `idle` deliveries with no fake timers required (`deferred` deliveries also fire after `await Promise.resolve()`).
- **`listen()`**: simulates a mounted component subscribing to the store so `onActive` runs, and returns the unsubscribe function to test cleanup.
- **`server()`**: returns `{ form, fields }` SSR snapshots (keyed by dotted path, with `""` for root) so you can verify deterministic server rendering with `expect(testStore(config).server()).toEqual(testStore(config).server())`.

`testStore` exercises core logic without a framework; pair it with a React or Solid component test if your plugin interacts with DOM elements or display text.
