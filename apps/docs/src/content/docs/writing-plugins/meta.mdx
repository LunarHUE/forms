`ctx.setMeta` and `ctx.setFormMeta` write the plugin's own slot on a field or
on the form. Annotate the context parameter of `setup` or `part` as
`PluginContext<M, F>` to type them. Read them back with the `meta` and
`formMeta` readers on the factory `definePlugin` returns, as
`history.formMeta(state)`.

A plugin with meta gives its starting value as `initialMeta` for fields or
`initialFormMeta` for the form. Leaving it out is a type error. The reader
returns it until the plugin sets its own, so a reader never returns undefined
unless `undefined` is part of the meta type. The reader works it out from the
snapshot alone, so the server and the first client render read the same value.
`history` starts from `{ canUndo: false, canRedo: false }`:

```ts
const history = definePlugin({
  name: "history",
  initialFormMeta: { canUndo: false, canRedo: false },
  setup(ctx: PluginContext<never, HistoryMeta>) {
    // ...
  },
});
```

Every field shares the one `initialMeta` value. Freeze it and keep it in one
place, so a selector that returns it gets the same object each time. `rules`
starts every field as shown:

```ts
const shown: RulesMeta = Object.freeze({ hidden: false });

const rules = definePlugin({
  name: "rules",
  initialMeta: shown,
  setup(ctx: PluginContext<RulesMeta>) {
    // ...
  },
});
```

Meta with no sensible start says so in its type, as `M | undefined` with
`initialMeta: undefined`.

`definePlugin` returns a `PluginFactory<A, N, M, F>`: the API, the name, the
field meta and the form meta, then the schemas, the plugins it requires, the
options and the part config. The factory has a `meta` reader when `M` isn't
`never`, and a `formMeta` reader when `F` isn't. `history` is a
`PluginFactory<HistoryApi, "history", never, HistoryMeta, never, readonly [], number | undefined>`,
and `history()` is the plugin it makes.

## Display text

A part can change what a field's text inputs show, as
[`masked`](../plugins/masks) does. These two hooks are for parts only:

- `display(value)`: the text to show for the stored value.
- `afterInput(input, value, event)`, optional: the adapter calls it after each
  edit in the input, once the typed text went to the store. `input` still
  holds the typed text and its caret, and `value` is the field's value now.
  Put the display text in `input` and place the caret.

When several parts on one field give a `display`, the first in hook order
wins. A display from a part that attaches before the store has listeners is
in the server HTML.

`text(display, afterInput?)` from `@lunarhue/forms-core/plugins` makes a part
with just these two. For `afterInput`, reuse `replaceText` from
`@lunarhue/forms-core/text`, or the same path under your adapter. It takes the
input, the text to show, a cleaner and the input event, and keeps the caret
the way `masked` does. Pass the cleaner the field's value goes through, so
the caret counts the characters the store keeps:

```ts
import { text, transform } from "@lunarhue/forms-core/plugins";
import { replaceText } from "@lunarhue/forms-core/text";

export const CardField = defineField(
  CardInput,
  transform<string>((value) => cleanCard(value)),
  text<string>(formatCard, (input, value, event) => replaceText(input, formatCard(value), cleanCard, event)),
);
```

For a cleaner and a display with nothing else, `masked({ clean, display })`
from `@lunarhue/forms-core/text` makes the same part. A plugin's `part` hook
can return `display` and `afterInput` alongside its other hooks.
